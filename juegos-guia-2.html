Cómo está organizada esta guía

Cada uno de los 3 juegos sigue la misma estructura: primero se explican, en un lenguaje sencillo, los conceptos de JavaScript que ese juego necesita; después se construye el HTML, luego el CSS y por último el JavaScript, mostrando el código completo de cada archivo (nada se deja fuera ni se resume con puntos suspensivos). Entre paso y paso encontrarás un checkpoint visual: una imagen que muestra cómo debe verse tu juego en ese punto, para que compares tu resultado.

El código de esta guía está bloqueado para copiar y pegar a propósito. Transcríbelo a mano en tu propio editor: escribir cada línea te obliga a leerla con atención.
No hay ningún entorno para ejecutar código dentro de esta guía. Debes crear los archivos index.html, style.css y script.js en tu computador y abrirlos en tu navegador para probarlos.
Los "checkpoints" son imágenes (dibujadas en SVG) que muestran el aspecto y el contenido esperado de tu juego en un momento dado, no el código ni una demostración interactiva.
Juego 1

Triki (Tic Tac Toe)

Dos jugadores usan el mismo dispositivo y se turnan para marcar casillas con "X" y "O". Gana quien complete primero una línea de tres, ya sea horizontal, vertical o diagonal.

Conceptos que necesitas

Un array como tablero

En vez de una cuadrícula 3x3, guardamos las 9 casillas en un solo array de 9 posiciones (índices 0 a 8), lo que facilita revisar y comparar valores.

Array de combinaciones ganadoras

Una lista fija con las 8 formas posibles de ganar (3 filas, 3 columnas y 2 diagonales), cada una guardada como un array de 3 índices.

Bucle for

Recorre el array de combinaciones ganadoras una por una, comprobando si las tres casillas de esa combinación tienen el mismo valor y no están vacías.

array.every()

Devuelve true solo si todos los elementos del array cumplen una condición. Lo usamos para saber si el tablero ya está lleno (empate).

Operador ternario

condición ? valorSiVerdadero : valorSiFalso es una forma corta de escribir un if/else en una sola línea; lo usamos para alternar el turno entre "X" y "O".

Delegación de eventos

Un único addEventListener en el tablero completo detecta el clic sobre cualquiera de las 9 casillas, incluso creadas dinámicamente con JavaScript.

Paso 1: estructura HTML

Igual que el tablero del juego de memoria de la guía anterior, las 9 casillas no se escriben a mano: solo preparamos un contenedor vacío, y JavaScript construye las casillas dentro de él a partir del array del tablero.

El <span id="turnoActual"> muestra de quién es el turno sin tener que reescribir toda la frase. El <div id="tableroTresEnRaya"> empieza vacío: su contenido lo genera por completo el JavaScript del Paso 3.

Checkpoint visual 1 de 3

Tablero recién generado: 9 casillas vacías y el turno inicial marcado como "X".

Paso 2: estilos CSS

El CSS organiza las 9 casillas en una cuadrícula de 3 columnas y les da tamaño y tipografía uniformes.

grid-template-columns: repeat(3, 90px) crea exactamente 3 columnas de 90 píxeles cada una; al haber 9 celdas, se acomodan solas en 3 filas. .celda.ganadora es la clase que resaltará en verde las tres casillas de la combinación ganadora.

Paso 3: lógica en JavaScript

Aquí se dibuja el tablero, se controlan los turnos y se comprueba si alguien ganó o si hubo empate.

combinacionesGanadoras es un array de 8 arrays, cada uno con los 3 índices (del 0 al 8) que forman una línea ganadora. tablero es el array de 9 posiciones que representa el estado real del juego; empieza con 9 cadenas vacías. turno guarda de quién es el turno actual, y juegoTerminado es la bandera que bloquea más clics una vez que alguien ganó o hubo empate.

crearTablero() vacía el contenedor y recorre el array tablero con forEach, creando una <div class="celda"> por cada posición. Cada celda guarda su posición en celda.dataset.indice y muestra el valor actual de esa posición ("X", "O" o vacío) como su texto.

verificarGanador() recorre combinacionesGanadoras con un for clásico. En cada vuelta, extrae los tres índices de la combinación (a, b, c) y comprueba dos cosas a la vez: que la casilla a no esté vacía, y que las tres casillas (a, b y c) tengan exactamente el mismo valor. Si encuentra una combinación así, devuelve ese valor ("X" u "O") de inmediato con return; si termina de recorrer todo el array sin encontrar ninguna, devuelve null.

verificarEmpate() usa tablero.every(...) para comprobar que ninguna posición del array siga vacía; si todas las casillas tienen algo, es empate.

El addEventListener("click") está en el contenedor del tablero completo (delegación de eventos), no en cada celda. Tras encontrar la celda clicada con closest(".celda"), se descartan los clics inválidos: que no haya celda, que el juego ya haya terminado, o que esa celda ya tenga un valor. Si el clic es válido, se guarda el turno actual en esa posición del array (tablero[indice] = turno) y se vuelve a dibujar el tablero completo con crearTablero().

Después de dibujar, se llama a verificarGanador(): si devuelve un valor, se muestra el mensaje de victoria y se activa juegoTerminado. Si no hay ganador, se revisa verificarEmpate(); si tampoco hay empate, se cambia el turno con el operador ternario turno = turno === "X" ? "O" : "X", que en una sola línea dice "si el turno actual es X, ahora es O; si no, ahora es X".

El botón de reinicio vuelve a llenar tablero con 9 cadenas vacías, restablece el turno a "X", quita la bandera juegoTerminado, limpia el mensaje y vuelve a dibujar el tablero desde cero.

Partida a medias: dos X y una O ya colocadas, es el turno de O.

Checkpoint visual 3 de 3

Fin de la partida: la fila superior de X quedó resaltada en verde y aparece el mensaje "Ganó X."

Juego 2

Simon dice

La computadora enciende una secuencia de colores, cada vez un poco más larga. El jugador debe repetir esa secuencia haciendo clic en los mismos botones y en el mismo orden.

Conceptos que necesitas

Un array como secuencia

La secuencia de colores a repetir se guarda como un array de números; cada número representa la posición de un color en la lista de botones.

array.push()

Agrega un nuevo elemento al final de un array. Cada ronda, se agrega un color aleatorio más a la secuencia con este método.

setInterval() y clearInterval()

setInterval repite una función cada cierto tiempo, útil para ir mostrando un color de la secuencia tras otro; clearInterval lo detiene cuando ya se mostraron todos.

setTimeout() para pausas

Se usa para apagar un botón después de un momento de estar encendido, y para dar una pequeña pausa antes de iniciar la siguiente ronda.

Comparar dos arrays paso a paso

En vez de comparar arrays completos, se compara elemento por elemento a medida que el jugador hace clic, para detectar el error apenas ocurre.

Una variable "bloqueado"

Evita que el jugador haga clic mientras la computadora todavía está mostrando la secuencia, o mientras se prepara la siguiente ronda.

Paso 1: estructura HTML

Necesitamos 4 botones de color (cada uno con su propio id y un data-color con su posición numérica), un contador de ronda, un mensaje y un botón para iniciar el juego.

El atributo data-color de cada botón coincide con su posición dentro de document.querySelectorAll(".colorSimon") (0, 1, 2 y 3), lo que permite relacionar directamente un color con una posición numérica dentro de la secuencia.

Checkpoint visual 1 de 3

Estado inicial: los 4 colores en reposo (semi-transparentes), ronda en 0, listo para presionar "Iniciar juego".

Paso 2: estilos CSS

El CSS acomoda los 4 botones en una cuadrícula de 2x2, les da color propio a cada uno, y define cómo se ven "encendidos".

Cada botón tiene opacity: 0.55 por defecto (apagado); la clase .activo, que JavaScript agrega y quita brevemente, sube la opacidad a 1 para simular que el botón se "enciende".

Paso 3: lógica en JavaScript

La parte más particular de este juego es la reproducción de la secuencia con una pausa entre cada color, y la comparación en tiempo real de lo que hace el jugador.

secuencia es el array con el orden correcto de colores (números del 0 al 3) que el jugador debe repetir; secuenciaUsuario guarda lo que el jugador ha ido presionando en la ronda actual; bloqueado empieza en true porque al inicio el jugador todavía no debe poder hacer clic.

generarPaso() elige un número aleatorio entre 0 y la cantidad de botones (usando Math.floor(Math.random() * botonesColor.length)) y lo agrega al final de secuencia con push.

encenderBoton(indiceColor) le agrega la clase "activo" al botón correspondiente y, con setTimeout, se la quita 400 milisegundos después, logrando el efecto de parpadeo.

reproducirSecuencia() bloquea el juego, reinicia secuenciaUsuario a un array vacío y actualiza el número de ronda. Usa setInterval para ir encendiendo, cada 700 milisegundos, el color que corresponde según la variable indice (que empieza en 0 y aumenta en cada vuelta). Cuando indice llega al tamaño de secuencia, se detiene el intervalo con clearInterval y, tras una breve pausa con setTimeout, se desbloquea el juego para que el jugador pueda responder.

En el clic de cada botón de color: si bloqueado es verdadero, no pasa nada. Si no, se enciende el botón presionado (para dar retroalimentación visual) y se agrega su color a secuenciaUsuario. Con pasoActual (la última posición agregada) se compara secuenciaUsuario[pasoActual] contra secuencia[pasoActual]: si no coinciden, el jugador se equivocó, se muestra un mensaje con la ronda alcanzada y se vuelve a bloquear el juego. Si coinciden y además secuenciaUsuario ya tiene la misma longitud que secuencia, el jugador completó la ronda correctamente: se muestra un mensaje de éxito y, tras una pausa, se llama de nuevo a generarPaso() y reproducirSecuencia() para la siguiente ronda, ahora un color más larga.

El botón "Iniciar juego" reinicia ambos arrays, limpia el mensaje, genera el primer color de la secuencia y la reproduce, comenzando la partida desde cero.

Checkpoint visual 2 de 3

La computadora está mostrando la secuencia: el color verde se encendió (opacidad completa) mientras los demás siguen atenuados.

Checkpoint visual 3 de 3

El jugador falló la secuencia: mensaje de error indicando en qué ronda quedó, colores de nuevo en reposo.

Juego 3

Ahorcado

La computadora elige en secreto una palabra. El jugador va proponiendo letras usando un teclado en pantalla; cada acierto revela esa letra en la palabra, y cada error dibuja una parte más de la figura.

Conceptos que necesitas

string.split("")

Convierte un texto en un array de sus caracteres individuales, por ejemplo "sol".split("") produce ["s", "o", "l"]. Lo usamos para recorrer letra por letra.

array.map()

Recorre un array y devuelve un array nuevo transformando cada elemento; lo usamos para convertir cada letra en sí misma (si ya fue adivinada) o en un guion bajo (si no).

array.indexOf()

Devuelve la posición de un valor dentro de un array, o -1 si no está. Nos sirve para comprobar si una letra ya fue adivinada o si pertenece a la palabra secreta.

array.join(" ")

Une todos los elementos de un array en un solo texto, separados por lo que le indiques. Lo usamos para mostrar la palabra oculta con espacios entre cada letra.

Generar botones con un bucle

En vez de escribir 26 botones a mano en el HTML, se recorre el abecedario con forEach y se crea un botón por cada letra con createElement.

Dibujo progresivo con SVG

Se guarda cada parte del dibujo del ahorcado en un array de fragmentos SVG, y se van agregando uno a uno según la cantidad de errores cometidos.

Paso 1: estructura HTML

Necesitamos un espacio para el dibujo, un párrafo para la palabra oculta, un contenedor vacío para el teclado (que JavaScript va a llenar con 26 botones), un mensaje y un botón de reinicio.

Tanto <div id="dibujoAhorcado"> como <div id="tecladoAhorcado"> empiezan vacíos: el primero se llena con el SVG del dibujo según los errores cometidos, y el segundo con los 26 botones de letras, ambos generados desde JavaScript.

Checkpoint visual 1 de 3

Estado inicial: gallows solo con la base (sin figura), la palabra secreta oculta con guiones bajos, y el teclado completo habilitado.

Paso 2: estilos CSS

El CSS da formato al teclado (una cuadrícula flexible de botones pequeños) y a la palabra oculta (con espaciado entre letras para que se lea con claridad).

.teclaAhorcado:disabled define cómo se ve un botón después de haber sido presionado (semi-transparente y sin cursor de clic), para que sea evidente qué letras ya se usaron.

Paso 3: lógica en JavaScript

Esta es la lógica más larga de la guía: elegir palabra, generar el teclado, comprobar cada letra, dibujar el ahorcado progresivamente y detectar victoria o derrota.

palabras es el array de palabras posibles; palabraSecreta se elige con un índice aleatorio, igual que en el Juego 1 de la guía anterior. letrasAdivinadas es un array vacío que se va llenando con cada acierto, errores empieza en 0, y maxErrores guarda el límite (6) antes de perder.

crearDibujoAhorcado(errores) tiene un array partes con 6 fragmentos SVG (cabeza, cuerpo, brazo izquierdo, brazo derecho, pierna izquierda y pierna derecha) y una base fija con el poste y la soga. Con un for que va de 0 hasta errores, se van concatenando al texto contenido solamente las primeras errores partes del array; así, con 0 errores solo se ve la base, y con 6 se ve la figura completa.

mostrarPalabra() convierte palabraSecreta en un array de letras con split(""), y con map transforma cada letra: si está en letrasAdivinadas (comprobado con indexOf distinto de -1), se muestra la letra real; si no, se muestra un guion bajo. El array resultante se convierte en texto con join(" "), dejando un espacio entre cada carácter para que se lea como una palabra con espacios entre letras.

verificarVictoria() usa every sobre las letras de la palabra secreta para comprobar que todas, sin excepción, ya estén en letrasAdivinadas.

crearTeclado() vacía el contenedor y recorre el abecedario (obtenido con "abcdefghijklmnopqrstuvwxyz".split("")) con forEach, creando un botón por cada letra con createElement, guardando la letra tanto en el texto del botón como en dataset.letra.

El addEventListener("click") del teclado usa delegación de eventos: encuentra el botón exacto con closest(".teclaAhorcado"), y descarta el clic si no hay botón, si ya está deshabilitado, o si el juego ya terminó. Si el clic es válido, se deshabilita ese botón de inmediato (boton.disabled = true) para que no se pueda volver a usar la misma letra. Con palabraSecreta.indexOf(letra) se comprueba si la letra está en la palabra: si sí, se agrega a letrasAdivinadas y se vuelve a mostrar la palabra, revisando además si eso implica la victoria; si no, se suma un error, se vuelve a dibujar el ahorcado con la nueva cantidad de errores, y se comprueba si se llegó al máximo permitido para declarar la derrota.

El botón de reinicio elige una nueva palabra secreta al azar, vacía letrasAdivinadas, pone errores en 0, quita la bandera de juego terminado, limpia el mensaje, vuelve a dibujar el ahorcado sin partes, actualiza la palabra oculta y reconstruye el teclado completo (con todos los botones habilitados de nuevo).

Partida en curso: se adivinaron "a" y "r" (letras reveladas en la palabra), se falló con "d" (botón deshabilitado y en gris), y el dibujo ya muestra cabeza y cuerpo (2 errores).

Checkpoint visual 3 de 3

Fin de la partida por errores: la figura del ahorcado está completa (6 errores) y se revela la palabra correcta en el mensaje.

Como siguiente paso, intenta agregar un marcador de partidas ganadas al Triki, un modo más difícil en Simon dice (colores más rápidos), o una lista más larga de palabras en el Ahorcado.
