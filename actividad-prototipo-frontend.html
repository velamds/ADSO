Actividad: prototipo de frontend para tu proyecto formativo

Diseña y construye, por tu cuenta, todas las interfaces que necesita el frontend de tu proyecto formativo. El prototipo debe funcionar completamente con datos de prueba que tú mismo definas y cargues, sin depender de un backend real.

Objetivo

¿Qué vas a hacer en esta actividad?

Vas a diseñar y construir el prototipo del frontend de tu propio proyecto formativo: todas las pantallas que un usuario necesitaría para usarlo, funcionando de principio a fin con información de ejemplo que tú mismo inventes, sin necesidad de un servidor ni de una base de datos real.

Objetivos de aprendizaje

Traducir un proyecto real a pantallas

Convertir la idea general de tu proyecto formativo en una lista concreta de interfaces que un usuario necesitaría usar.

Diseñar antes de programar

Practicar la elaboración de bocetos o wireframes de baja fidelidad antes de escribir una sola línea de código.

Simular datos reales

Definir arrays y objetos de JavaScript que representen de forma creíble la información con la que trabajará tu proyecto.

Aplicar manipulación del DOM

Usar todo lo practicado en las guías anteriores (selección, eventos, creación de elementos, delegación, localStorage) en un proyecto propio.

Requisitos

Requisitos del prototipo

Estas condiciones aplican sin importar cuál sea tu proyecto formativo. Márcalas a medida que las vayas cumpliendo.

  • El prototipo cubre todas las pantallas necesarias para que un usuario complete al menos un flujo completo de tu proyecto de principio a fin (por ejemplo: iniciar sesión, ver un listado, crear un registro, ver su detalle y editarlo o eliminarlo).
  • Todos los datos que se muestran (listados, detalles, formularios prellenados, etc.) provienen de datos de prueba que tú definiste como arrays u objetos de JavaScript, no de texto escrito directamente en el HTML.
  • Las acciones principales (agregar, editar, eliminar, marcar, filtrar, buscar, según lo que aplique a tu proyecto) funcionan de verdad sobre esos datos de prueba, actualizando lo que se ve en pantalla.
  • La navegación entre pantallas funciona (mostrando y ocultando secciones, o usando varias páginas HTML enlazadas), de forma que se sienta como una sola aplicación.
  • El diseño visual (colores, tipografía, espaciados) es consistente entre todas las pantallas del prototipo.
  • El código HTML, CSS y JavaScript está organizado en archivos separados y es legible (nombres de variables y funciones claros, indentación consistente).
  • Opcional (bono): los datos de prueba se guardan con localStorage, de modo que los cambios sobreviven a recargar la página.
No necesitas conectar tu prototipo a un servidor, una API ni una base de datos real. Todo el "backend" de esta actividad son los datos de prueba que tú mismo escribas en JavaScript.
Metodología

Cómo abordar la actividad, paso a paso

No es obligatorio seguir este orden exacto, pero se recomienda para no quedarte atascado diseñando o programando todo al mismo tiempo.

1

Define tu proyecto y sus módulos principales

Escribe en una frase de qué trata tu proyecto formativo, y luego divídelo en 3 a 6 módulos o funcionalidades grandes (por ejemplo: gestión de inventario, gestión de clientes, reportes, autenticación).

2

Lista las pantallas que necesita cada módulo

Por cada módulo, identifica qué pantallas hacen falta: normalmente un listado, un formulario de creación o edición, y a veces una vista de detalle o un panel con indicadores.

3

Dibuja wireframes de baja fidelidad

En papel, en una pizarra digital o en una herramienta de diseño, dibuja un boceto simple de cada pantalla: cajas y líneas que indiquen dónde va cada elemento, sin preocuparte todavía por colores ni tipografías definitivas.

4

Define tus datos de prueba

Antes de programar la interfaz, escribe en JavaScript los arrays de objetos que van a simular la información real de tu proyecto (ver la sección "Datos de prueba" más abajo para ideas).

5

Construye el HTML base de cada pantalla

Crea la estructura de cada pantalla con HTML, dejando vacíos los contenedores que luego JavaScript va a llenar con información dinámica (listas, tarjetas, filas de tabla).

6

Aplica un estilo visual consistente

Define una paleta de colores y una tipografía, y reutilízalas en todas las pantallas para que el prototipo se sienta como una sola aplicación, no como páginas sueltas.

7

Programa la lógica de cada pantalla

Usa las técnicas ya practicadas: una función que "pinta" los datos en pantalla, delegación de eventos para los botones de acción, y funciones que agregan, editan o eliminan elementos de tus arrays de datos de prueba.

8

Prueba con distintos escenarios

Verifica que tu prototipo se comporte bien con una lista vacía, con un solo elemento, con muchos elementos, y con datos "raros" (nombres muy largos, precios en cero, campos vacíos).

9

(Opcional) agrega persistencia con localStorage

Si te sobra tiempo, guarda tus datos de prueba en localStorage para que los cambios no se pierdan al recargar la página, tal como se hizo en la guía del carrito de compras.

Tipos de interfaz

Patrones frecuentes de interfaz

Casi cualquier proyecto formativo se puede construir combinando algunos patrones de interfaz muy comunes. Estos wireframes son solo ejemplos genéricos para inspirarte: debes diseñar los tuyos, con los campos y datos específicos de tu proyecto.

Listado con filtros

Un buscador o filtro arriba, y una tabla o lista de registros abajo. Sirve para inventarios, catálogos, historiales, listas de usuarios, etc.

Formulario de creación o edición

Campos etiquetados y un botón de guardar. Sirve para registrar productos, agendar citas, dar de alta usuarios, crear pedidos, etc.

Vista de detalle

Muestra toda la información de un solo registro, con botones para editarlo o eliminarlo. Sirve para ver el perfil de un cliente, el detalle de un pedido, la ficha de un producto, etc.

Panel con indicadores

Tarjetas con números clave arriba y un gráfico simple abajo. Sirve para mostrar totales, resúmenes o estadísticas generales del proyecto.

Inicio de sesión o registro

Una tarjeta centrada con campos de acceso y un botón principal. Útil si tu proyecto necesita simular distintos tipos de usuario.

Estructura general con menú lateral

Un menú fijo a la izquierda para moverse entre los módulos, y el contenido de cada pantalla a la derecha. Útil como "esqueleto" que envuelve a todas las demás pantallas.

No todos los proyectos necesitan los 6 patrones. Elige y combina solo los que tengan sentido para el tuyo, y agrega pantallas propias si tu proyecto necesita algo distinto (por ejemplo, un calendario, un mapa o un carrito de compras).
Datos de prueba

Cómo definir tus propios datos de prueba

Antes de construir cualquier pantalla, define en JavaScript los arrays de objetos que van a simular la información real de tu proyecto. Aquí tienes tres ejemplos de proyectos distintos para inspirarte; el tuyo tendrá campos diferentes según lo que necesite.

Ejemplo 1 · Sistema de inventario
const productos = [ { id: 1, nombre: "Cemento gris x50kg", categoria: "Materiales", stock: 120, precio: 32000 }, { id: 2, nombre: "Martillo de uña", categoria: "Herramientas", stock: 8, precio: 25000 }, { id: 3, nombre: "Guantes de seguridad", categoria: "Dotación", stock: 45, precio: 9000 } ];
Ejemplo 2 · Agenda de citas
const citas = [ { id: 1, cliente: "Laura Gómez", servicio: "Corte de cabello", fecha: "2026-09-22", hora: "10:00", estado: "confirmada" }, { id: 2, cliente: "Andrés Ruiz", servicio: "Manicure", fecha: "2026-09-22", hora: "11:30", estado: "pendiente" } ];
Ejemplo 3 · Biblioteca
const libros = [ { id: 1, titulo: "Cien años de soledad", autor: "Gabriel García Márquez", disponible: true }, { id: 2, titulo: "El principito", autor: "Antoine de Saint-Exupéry", disponible: false } ];

Recomendaciones para tus datos de prueba

Usa entre 5 y 10 registros

Suficientes para que un listado se vea real y puedas probar filtros o búsquedas, pero no tantos que sea difícil de leer mientras programas.

Incluye variedad

Agrega registros con distintos estados (activo/inactivo, pagado/pendiente), valores altos y bajos, y textos cortos y largos, para probar que tu interfaz aguanta casos distintos.

Dale a cada registro un id único

Igual que en las guías anteriores, un campo id te permite encontrar, editar o eliminar un registro concreto con find o filter.

Prueba el caso "vacío"

Antes de entregar, prueba qué se ve en pantalla si el array de datos está completamente vacío: tu interfaz debería mostrar un mensaje claro, no quedar en blanco.

Entregables

Qué debes entregar

  • Bocetos o wireframes de cada pantalla (fotos de tus dibujos en papel, o capturas de la herramienta de diseño que hayas usado).
  • Código fuente completo del prototipo (archivos HTML, CSS y JS), organizado en carpetas si tiene varias páginas.
  • Un documento corto (media página es suficiente) explicando: de qué trata tu proyecto, qué módulos cubriste en el prototipo, y qué datos de prueba usaste.
  • El prototipo funcionando, listo para abrir y probar sin instalar nada adicional.
Consejo final: empieza por la pantalla más simple de tu proyecto (normalmente un listado), consíguela funcionando por completo con tus datos de prueba, y solo después avanza a la siguiente. Es mejor tener 3 pantallas completamente funcionales que 8 pantallas a medias.
