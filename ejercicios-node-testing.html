Cada ejercicio incluye un ejemplo base que puedes tomar como referencia. Lee el ejemplo, entiende el patrón y luego implementa el ejercicio propuesto. No hay soluciones — el objetivo es que explores y te equivoques.

Node.js · Jest Ejercicio 1 — NumberUtils Fácil

Empezamos con funciones puras: reciben entradas, devuelven una salida, no modifican estado externo. Son las más sencillas de testear porque no requieren mocks ni clases.

Ejemplo base Funciones isEven y safeSquareRoot

Lee este ejemplo antes de hacer el ejercicio. Observa la estructura del archivo de producción y del test.

📄 src/mathBasics.js
// Devuelve true si n es par, false si es impar
function isEven(n) {
  if (typeof n !== 'number' || !Number.isInteger(n)) {
    throw new TypeError('Se esperaba un entero.');
  }
  return n % 2 === 0;
}

// Devuelve la raíz cuadrada o lanza error si n es negativo
function safeSquareRoot(n) {
  if (n < 0) throw new RangeError('No se puede calcular la raíz de un número negativo.');
  return Math.sqrt(n);
}

module.exports = { isEven, safeSquareRoot };
🧪 __tests__/mathBasics.test.js
const { isEven, safeSquareRoot } = require('../src/mathBasics');

describe('mathBasics', () => {

  describe('isEven()', () => {
    it('devuelve true para un número par', () => {
      // Arrange
      const n = 4;
      // Act
      const result = isEven(n);
      // Assert
      expect(result).toBe(true);
    });

    it('devuelve false para un número impar', () => {
      expect(isEven(7)).toBe(false);
    });

    it('funciona con el número 0 (es par)', () => {
      expect(isEven(0)).toBe(true);
    });

    it('lanza TypeError si el argumento no es un entero', () => {
      expect(() => isEven('hola')).toThrow(TypeError);
      expect(() => isEven(3.5)).toThrow(TypeError);
    });
  });

  describe('safeSquareRoot()', () => {
    it('devuelve la raíz cuadrada correcta', () => {
      expect(safeSquareRoot(9)).toBe(3);
      expect(safeSquareRoot(0)).toBe(0);
    });

    it('lanza RangeError para números negativos', () => {
      expect(() => safeSquareRoot(-4)).toThrow(RangeError);
      expect(() => safeSquareRoot(-4)).toThrow('negativo');
    });
  });

});
🔍
¿Qué observar en este ejemplo?

Cada describe() agrupa los tests de una función. Se prueban tanto casos exitosos como casos borde (0) y casos de error. Para errores se usa la forma expect(() => funcion()).toThrow(...).

Tu turno — Implementa numberUtils.js
Crea el archivo de producción y luego sus tests

Implementa en src/numberUtils.js las siguientes tres funciones. Luego escribe sus tests en __tests__/numberUtils.test.js.

Función 1 — factorial(n)
  • Devuelve el factorial de n (ejemplo: factorial(5) → 120).
  • factorial(0) debe devolver 1 (por definición matemática).
  • Si n es negativo, lanza un RangeError.
  • Si n no es un entero, lanza un TypeError.
Función 2 — isPrime(n)
  • Devuelve true si n es un número primo, false en caso contrario.
  • Los números menores a 2 no son primos (incluyendo 0 y 1).
  • Ejemplos de primos: 2, 3, 5, 7, 11, 13…
Función 3 — clamp(value, min, max)
  • Devuelve value si está entre min y max.
  • Si value es menor que min, devuelve min.
  • Si value es mayor que max, devuelve max.
  • Si min > max, lanza un RangeError.
Tests requeridos (mínimo 2 por función)
  • factorial: caso normal, caso de n=0, negativo, decimal.
  • isPrime: primo conocido, no primo, 0, 1, número negativo.
  • clamp: valor dentro del rango, valor menor, valor mayor, min === max, min > max.
  • Para factorial, puedes usar recursión o un bucle for. Ambos son válidos.
  • Para isPrime, el algoritmo más sencillo es verificar divisibilidad desde 2 hasta Math.floor(Math.sqrt(n)).
  • Para clamp, Math.min(Math.max(value, min), max) es una forma elegante de implementarlo en una línea.
  • Prueba siempre el valor exacto en el límite: si el rango es [1, 10], prueba con clamp(1, 1, 10) y clamp(10, 1, 10).
  • Recuerda exportar las funciones con module.exports = { factorial, isPrime, clamp };

Node.js · Jest Ejercicio 2 — StringProcessor Fácil

Las funciones de procesamiento de texto son un excelente campo de práctica: tienen entradas y salidas claras, y hay muchos casos borde interesantes (texto vacío, espacios, caracteres especiales).

Ejemplo base Funciones capitalize y countOccurrences
📄 src/textBasics.js
// Convierte la primera letra a mayúscula, el resto a minúscula
function capitalize(text) {
  if (typeof text !== 'string') throw new TypeError('Se esperaba un string.');
  if (text.trim() === '') return '';
  return text.charAt(0).toUpperCase() + text.slice(1).toLowerCase();
}

// Cuenta cuántas veces aparece `substring` dentro de `text`
function countOccurrences(text, substring) {
  if (!substring) return 0;
  let count = 0;
  let index = text.indexOf(substring);
  while (index !== -1) {
    count++;
    index = text.indexOf(substring, index + 1);
  }
  return count;
}

module.exports = { capitalize, countOccurrences };
🧪 __tests__/textBasics.test.js
const { capitalize, countOccurrences } = require('../src/textBasics');

describe('textBasics', () => {

  describe('capitalize()', () => {
    it('pone en mayúscula la primera letra', () => {
      expect(capitalize('hola mundo')).toBe('Hola mundo');
    });

    it('convierte el resto a minúsculas', () => {
      expect(capitalize('JAVASCRIPT')).toBe('Javascript');
    });

    it('devuelve cadena vacía si el texto está vacío o es solo espacios', () => {
      expect(capitalize('')).toBe('');
      expect(capitalize('   ')).toBe('');
    });

    it('lanza TypeError si el argumento no es un string', () => {
      expect(() => capitalize(42)).toThrow(TypeError);
    });
  });

  describe('countOccurrences()', () => {
    it('cuenta correctamente las apariciones', () => {
      expect(countOccurrences('banana', 'a')).toBe(3);
    });

    it('devuelve 0 si el substring no aparece', () => {
      expect(countOccurrences('hola', 'z')).toBe(0);
    });

    it('devuelve 0 si el substring es una cadena vacía', () => {
      expect(countOccurrences('hola', '')).toBe(0);
    });
  });

});
🔍
¿Qué observar en este ejemplo?

Se prueban explícitamente los casos borde: texto vacío, solo espacios, y substring vacío. Estos casos "raros" son donde el código suele fallar. Antes de escribir un test, pregúntate: ¿qué pasa si el usuario manda un string vacío?

✏️
Tu turno — Implementa stringProcessor.js
Enfócate en los casos borde: texto vacío, espacios extras, caracteres especiales

Implementa en src/stringProcessor.js las siguientes funciones y escribe sus tests en __tests__/stringProcessor.test.js.

Función 1 — maskEmail(email)
  • Oculta el usuario del email dejando solo el primer y último carácter visibles.
  • Ejemplo: "sergio@gmail.com" → "s*****o@gmail.com"
  • Si el usuario tiene solo 1 carácter, devuelve el email sin cambios.
  • Si el email no contiene @, lanza un Error.
Función 2 — reverseWords(sentence)
  • Invierte el orden de las palabras (no de los caracteres) en la oración.
  • Ejemplo: "hola mundo node" → "node mundo hola"
  • Debe manejar espacios múltiples entre palabras.
  • Si el texto está vacío o es solo espacios, devuelve "".
Función 3 — extractHashtags(text)
  • Devuelve un array con todos los hashtags encontrados en el texto.
  • Ejemplo: "Me gusta #node y #testing" → ["#node", "#testing"]
  • Si no hay hashtags, devuelve un array vacío [].
  • El # solo cuenta como hashtag si le sigue al menos una letra o número.
Tests requeridos (mínimo 2 por función)
  • maskEmail: email normal, usuario de 1 char, email sin @.
  • reverseWords: oración normal, espacios múltiples, texto vacío, una sola palabra.
  • extractHashtags: múltiples hashtags, sin hashtags, # solo (sin texto después).
  • Para maskEmail: usa email.split('@') para separar usuario y dominio. Luego construye la máscara con '*'.repeat(n).
  • Para reverseWords: sentence.trim().split(/\s+/).reverse().join(' ') es una forma compacta. /\s+/ maneja múltiples espacios.
  • Para extractHashtags: la expresión regular /#\w+/g captura hashtags con text.match(/#\w+/g). Recuerda que match() devuelve null si no hay coincidencias.
  • Prueba extractHashtags con texto que tenga un # solo o al final de la cadena.

Node.js · Jest Ejercicio 3 — TaskManager Intermedio

Cuando el código tiene estado interno (variables que cambian entre llamadas), es fundamental usar beforeEach() para resetear ese estado antes de cada test. De lo contrario, los tests se contaminan entre sí.

Ejemplo base Clase Stack con beforeEach
📄 src/stack.js
class Stack {
  constructor() {
    this._items = [];
  }

  push(item) {
    this._items.push(item);
  }

  pop() {
    if (this.isEmpty()) throw new Error('El stack está vacío.');
    return this._items.pop();
  }

  peek() {
    if (this.isEmpty()) throw new Error('El stack está vacío.');
    return this._items[this._items.length - 1];
  }

  isEmpty() {
    return this._items.length === 0;
  }

  get size() {
    return this._items.length;
  }
}

module.exports = Stack;
🧪 __tests__/stack.test.js
const Stack = require('../src/stack');

describe('Stack', () => {
  let stack;

  // beforeEach garantiza que cada test empiece con un stack vacío
  beforeEach(() => {
    stack = new Stack();
  });

  it('inicia vacío', () => {
    expect(stack.isEmpty()).toBe(true);
    expect(stack.size).toBe(0);
  });

  it('push agrega elementos y aumenta el tamaño', () => {
    stack.push('A');
    stack.push('B');
    expect(stack.size).toBe(2);
  });

  it('pop devuelve el último elemento agregado', () => {
    stack.push(10);
    stack.push(20);

    const result = stack.pop();

    expect(result).toBe(20);
    expect(stack.size).toBe(1);   // queda un elemento
  });

  it('pop lanza error si el stack está vacío', () => {
    expect(() => stack.pop()).toThrow('El stack está vacío.');
  });

  it('peek devuelve el tope sin eliminarlo', () => {
    stack.push('X');
    expect(stack.peek()).toBe('X');
    expect(stack.size).toBe(1);   // sigue intacto
  });
});
🔍
¿Qué observar en este ejemplo?

beforeEach declara stack = new Stack() antes de cada test, así ningún test hereda el estado del anterior. También nota cómo se verifica el efecto secundario: después de pop() se comprueba que el tamaño disminuyó.

✏️
Tu turno — Implementa TaskManager
Una clase que gestiona tareas con estado interno

Implementa en src/taskManager.js la clase TaskManager y luego escribe sus tests en __tests__/taskManager.test.js.

Comportamiento esperado de TaskManager
  • addTask(title) — agrega una tarea con estructura { id, title, completed: false, createdAt: Date }. Si title está vacío, lanza un Error. Devuelve la tarea creada.
  • completeTask(id) — marca la tarea con ese id como completed: true. Si el id no existe, lanza un Error.
  • removeTask(id) — elimina la tarea con ese id. Si no existe, lanza un Error.
  • getPending() — devuelve solo las tareas con completed: false.
  • getCompleted() — devuelve solo las tareas con completed: true.
  • getAll() — devuelve todas las tareas.
Tests requeridos
  • Una tarea recién creada tiene completed: false.
  • Después de addTask, el total de tareas aumenta en 1.
  • completeTask cambia el estado correctamente sin afectar otras tareas.
  • removeTask disminuye el total de tareas.
  • getPending() no incluye tareas completadas.
  • getCompleted() no incluye tareas pendientes.
  • Los métodos que reciben un id inválido lanzan error.
  • addTask con title vacío lanza error.
  • Para generar IDs únicos, puedes usar un contador interno: this._nextId = 1 y hacer id: this._nextId++ en cada addTask.
  • Usa beforeEach en tus tests para crear una nueva instancia de TaskManager antes de cada test.
  • Para encontrar una tarea por ID: this._tasks.find(t => t.id === id).
  • Recuerda probar que las operaciones son inmutables para otras tareas: si completas la tarea 1, la tarea 2 no debe verse afectada.
  • getPending() puede implementarse con this._tasks.filter(t => !t.completed).

Node.js · Jest Ejercicio 4 — ProductService async Intermedio

El código real casi siempre trabaja con operaciones asíncronas (base de datos, APIs externas). Jest soporta async/await de forma nativa, y con jest.fn() podemos simular dependencias sin hacer llamadas reales.

Ejemplo base Clase UserService asíncrona con mock de repositorio
📄 src/userService.js
class UserService {
  constructor(userRepository) {
    this.repo = userRepository;  // dependencia inyectada
  }

  async findById(id) {
    if (typeof id !== 'number') throw new TypeError('id debe ser un número.');
    const user = await this.repo.findById(id);
    if (!user) throw new Error(`Usuario ${id} no encontrado.`);
    return user;
  }

  async getActiveUsers() {
    const all = await this.repo.findAll();
    return all.filter(u => u.active);
  }
}

module.exports = UserService;
🧪 __tests__/userService.test.js
const UserService = require('../src/userService');

// Repositorio simulado: objeto con funciones mockeadas
const mockRepo = {
  findById: jest.fn(),
  findAll:  jest.fn(),
};

describe('UserService', () => {
  let service;

  beforeEach(() => {
    jest.clearAllMocks();               // reset del historial entre tests
    service = new UserService(mockRepo);
  });

  describe('findById()', () => {
    it('devuelve el usuario cuando existe', async () => {
      // Arrange: el mock resolverá con este valor
      mockRepo.findById.mockResolvedValue({ id: 1, name: 'Ana', active: true });

      // Act
      const user = await service.findById(1);

      // Assert
      expect(user.name).toBe('Ana');
      expect(mockRepo.findById).toHaveBeenCalledWith(1);
      expect(mockRepo.findById).toHaveBeenCalledTimes(1);
    });

    it('lanza Error si el usuario no existe', async () => {
      mockRepo.findById.mockResolvedValue(null);  // simula "no encontrado"

      await expect(service.findById(99)).rejects.toThrow('Usuario 99 no encontrado.');
    });

    it('lanza TypeError si id no es un número', async () => {
      await expect(service.findById('abc')).rejects.toThrow(TypeError);
    });
  });

  describe('getActiveUsers()', () => {
    it('filtra solo usuarios activos', async () => {
      mockRepo.findAll.mockResolvedValue([
        { id: 1, name: 'Ana',  active: true  },
        { id: 2, name: 'Luis', active: false },
        { id: 3, name: 'Eva',  active: true  },
      ]);

      const result = await service.getActiveUsers();

      expect(result).toHaveLength(2);
      expect(result.every(u => u.active)).toBe(true);
    });
  });
});
🔍
¿Qué observar en este ejemplo?

jest.fn() crea una función vacía rastreable. mockResolvedValue() simula una promesa resuelta. mockRejectedValue() simula un error. jest.clearAllMocks() en beforeEach limpia el historial de llamadas para que los tests no se afecten entre sí.

Tu turno — Implementa ProductService
Código asíncrono con inyección de dependencias y mocks

Implementa en src/productService.js la clase ProductService. Esta clase recibe en su constructor un productRepository (que en producción hablaría con una BD, pero en los tests será un mock).

Contratos del repositorio (solo interfaces, no los implementes)
  • productRepository.findAll() — promesa que resuelve con array de productos.
  • productRepository.findById(id) — promesa que resuelve con un producto o null.
  • productRepository.save(product) — promesa que resuelve con el producto guardado.
Métodos de ProductService a implementar
  • async getById(id) — obtiene un producto por ID. Lanza Error si no existe.
  • async getByCategory(category) — obtiene todos los productos y filtra por product.category === category.
  • async searchByName(query) — obtiene todos los productos y filtra aquellos cuyo name contenga query (case-insensitive). Si query está vacío, lanza Error.
  • async create(productData) — valida que productData.name y productData.price existan y que price > 0. Si no, lanza Error. Si es válido, llama a repository.save() y devuelve el resultado.
Tests requeridos
  • getById: encontrado correctamente, no encontrado (lanza error), verifica que el repositorio fue llamado con el ID correcto.
  • getByCategory: devuelve solo los de esa categoría, categoría sin productos devuelve array vacío.
  • searchByName: búsqueda exitosa, búsqueda case-insensitive, query vacío lanza error.
  • create: producto válido llama a save(), precio negativo lanza error, nombre faltante lanza error, save() solo se llama una vez con datos válidos.
  • Crea el mockRepository con { findAll: jest.fn(), findById: jest.fn(), save: jest.fn() }.
  • Usa mockResolvedValue() para simular respuestas exitosas y mockRejectedValue(new Error(...)) para simular fallos del repositorio.
  • Para búsqueda case-insensitive: product.name.toLowerCase().includes(query.toLowerCase()).
  • Verifica las interacciones con el mock: expect(mockRepo.save).toHaveBeenCalledTimes(1) y expect(mockRepo.save).not.toHaveBeenCalled().
  • No olvides jest.clearAllMocks() en el beforeEach, o el historial de llamadas se acumulará entre tests.

Node.js · Jest Ejercicio 5 — API REST con Supertest Intermedio+

Supertest permite hacer peticiones HTTP a una app Express directamente en memoria, sin levantar un servidor real. Es la herramienta estándar para testear rutas en Node.js.

📦
Instalación de Supertest

Si aún no lo tienes: npm install --save-dev supertest. Tu app.js debe exportar la app con module.exports = app y sin llamar a app.listen() — eso lo hace Supertest internamente.

Ejemplo base API simple de notas con GET, POST y 404
📄 src/notesApp.js
const express = require('express');
const app = express();
app.use(express.json());

let notes = [
  { id: 1, text: 'Comprar leche', done: false },
  { id: 2, text: 'Estudiar Jest',  done: false },
];
let nextId = 3;

// GET todas las notas
app.get('/api/notes', (req, res) => {
  res.json(notes);
});

// GET una nota por ID
app.get('/api/notes/:id', (req, res) => {
  const note = notes.find(n => n.id === Number(req.params.id));
  if (!note) return res.status(404).json({ error: 'Nota no encontrada.' });
  res.json(note);
});

// POST crear una nota
app.post('/api/notes', (req, res) => {
  const { text } = req.body;
  if (!text || text.trim() === '') {
    return res.status(400).json({ error: 'El campo text es requerido.' });
  }
  const newNote = { id: nextId++, text: text.trim(), done: false };
  notes.push(newNote);
  res.status(201).json(newNote);
});

module.exports = app;   // sin app.listen()
🧪 __tests__/notesApp.test.js
const request = require('supertest');
const app = require('../src/notesApp');

describe('Notes API', () => {

  describe('GET /api/notes', () => {
    it('responde con status 200 y un array', async () => {
      const res = await request(app).get('/api/notes');

      expect(res.status).toBe(200);
      expect(Array.isArray(res.body)).toBe(true);
    });
  });

  describe('GET /api/notes/:id', () => {
    it('devuelve la nota correcta', async () => {
      const res = await request(app).get('/api/notes/1');

      expect(res.status).toBe(200);
      expect(res.body).toMatchObject({ id: 1, text: 'Comprar leche' });
    });

    it('devuelve 404 si la nota no existe', async () => {
      const res = await request(app).get('/api/notes/999');

      expect(res.status).toBe(404);
      expect(res.body).toHaveProperty('error');
    });
  });

  describe('POST /api/notes', () => {
    it('crea una nota y devuelve 201', async () => {
      const res = await request(app)
        .post('/api/notes')
        .send({ text: 'Nueva nota de prueba' });

      expect(res.status).toBe(201);
      expect(res.body).toMatchObject({ text: 'Nueva nota de prueba', done: false });
      expect(res.body.id).toBeDefined();
    });

    it('devuelve 400 si text está vacío', async () => {
      const res = await request(app)
        .post('/api/notes')
        .send({ text: '' });

      expect(res.status).toBe(400);
      expect(res.body.error).toMatch(/text/i);
    });
  });

});
🔍
¿Qué observar en este ejemplo?

request(app).get('/ruta') hace una petición HTTP real en memoria. Se verifican tanto el status HTTP como la estructura del cuerpo. toMatchObject verifica que el objeto contenga al menos esas propiedades (no necesariamente solo esas).

Tu turno — API REST de contactos
Construye la API y sus tests de integración con Supertest

Implementa en src/app.js una API de contactos con las rutas descritas abajo. Luego escribe los tests en __tests__/app.test.js usando Supertest.

Estructura de un contacto
  • id: número autoincremental
  • name: string (requerido)
  • email: string (requerido, debe contener @)
  • phone: string (opcional)
Rutas a implementar
  • GET /api/contacts — devuelve todos los contactos.
  • GET /api/contacts/:id — devuelve un contacto. Si no existe → 404.
  • POST /api/contacts — crea un contacto. Si falta name o email, o el email no tiene @ → 400 con mensaje de error.
  • PUT /api/contacts/:id — actualiza parcialmente un contacto existente. Si no existe → 404.
  • DELETE /api/contacts/:id — elimina un contacto. Si no existe → 404. Si se elimina correctamente → 200 con mensaje de confirmación.
Tests requeridos
  1. GET /api/contacts devuelve status 200 y un array.
  2. GET /api/contacts/:id devuelve el contacto correcto.
  3. GET /api/contacts/:id devuelve 404 para un ID inexistente.
  4. POST /api/contacts crea el contacto y devuelve 201 con el objeto creado.
  5. POST /api/contacts devuelve 400 si falta el name.
  6. POST /api/contacts devuelve 400 si el email no tiene @.
  7. PUT /api/contacts/:id actualiza correctamente los campos enviados.
  8. DELETE /api/contacts/:id elimina el contacto y devuelve confirmación.
  9. DELETE /api/contacts/:id devuelve 404 para ID inexistente.
⚠️
Problema de estado compartido entre tests

Si tu API guarda los contactos en un array en memoria, los tests se contaminarán entre sí porque el POST del test 4 puede afectar el resultado del test 1. Una solución es reiniciar los datos en un beforeEach, o exportar una función resetData() desde tu app que los tests puedan llamar.

  • Para PUT, usa Object.assign(contact, req.body) o el spread operator para actualizar solo los campos enviados sin reemplazar el objeto completo.
  • Para evitar contaminación entre tests, exporta una función resetContacts() que reinicie el array a datos iniciales, y llámala en beforeEach de los tests.
  • Valida el email con email.includes('@') — una validación simple es suficiente para este ejercicio.
  • Usa res.body.length para verificar cuántos elementos devuelve el GET después de agregar o eliminar.
  • Para el DELETE: res.status(200).json({ message: 'Contacto eliminado.' }) es un patrón común.
  • El id en los parámetros de ruta llega como string: usa Number(req.params.id) al buscar en el array.

Tips generales para escribir buenos tests

Nombra los tests con claridad

El nombre debe describir qué se prueba y qué se espera. Ejemplo: 'devuelve 404 si el id no existe' es mejor que 'test de id'.

Un test, un concepto

Evita verificar múltiples comportamientos en un solo it(). Si el test falla, debes saber exactamente qué falló.

Prueba los casos borde

Texto vacío, null, 0, arrays vacíos, valores en el límite exacto. Ahí vive la mayoría de los bugs.

Usa beforeEach

Siempre reinicia el estado compartido (instancias de clase, mocks) antes de cada test para garantizar independencia.

Verifica las interacciones

Con mocks, verifica no solo el resultado final sino también que las dependencias fueron llamadas correctamente: toHaveBeenCalledWith, toHaveBeenCalledTimes.
