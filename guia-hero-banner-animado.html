Banner (hero) animado con 3-4 imágenes

Vas a construir un banner de portada que rota automáticamente entre varias imágenes en bucle, con texto y un botón superpuestos. Todo el movimiento se logra con @keyframes de CSS — ni una línea de JavaScript.

🎯 Cada paso agrega una sola pieza nueva. Al final de cada uno hay un checkpoint que explica línea por línea lo que acabas de escribir, más un mini reto para que pruebes algo por tu cuenta antes de seguir. No se te entrega el archivo final completo para copiar y pegar — se indica exactamente qué agregar en cada paso, y al final ves el resultado funcionando.
Paso 1 · Estructura HTML

El contenedor del banner y sus 4 capas de imagen

El banner es una sección con 4 <div> vacíos (uno por imagen) y un bloque de texto. Cada imagen ocupará exactamente el mismo espacio, apiladas unas sobre otras como capas — eso lo resolverás con CSS en el paso 2.

Agrega esto en tu index.html
<section class="hero">
  <div class="slide slide-1"></div>
  <div class="slide slide-2"></div>
  <div class="slide slide-3"></div>
  <div class="slide slide-4"></div>

  <div class="hero-content">
    <h1>Explora el mundo a tu manera</h1>
    <p>Rutas, guías y experiencias diseñadas para ti.</p>
    <a href="#" class="btn">Ver destinos</a>
  </div>
</section>
Línea por línea
<section class="hero">Es el contenedor de todo el banner. Usamos <section> porque semánticamente agrupa una parte independiente de la página, y le damos la clase hero para poder estilizarla luego.
<div class="slide slide-1">Cada imagen del carrusel es un <div> vacío. Tiene dos clases: slide (estilos que comparten las 4 capas) y slide-1 (solo para esta capa: su imagen y su momento de aparición).
slide-2, slide-3, slide-4Se repite el mismo patrón 3 veces más — un div por cada imagen adicional del banner.
<div class="hero-content">El bloque de texto que se verá encima de las imágenes. Va después de los 4 slides en el HTML para que, cuando le des posicionamiento en el paso 4, quede naturalmente por encima en el orden de apilado.
<h1>, <p>, <a class="btn">Título, texto de apoyo y un botón — el contenido típico de cualquier hero: mensaje claro + llamado a la acción.
✅ Checkpoint
  • Al abrir el archivo en el navegador verás solo texto plano apilado verticalmente: título, párrafo y un enlace. Es normal — todavía no hay una sola línea de CSS.
  • Cuenta que tengas exactamente 4 .slide dentro de .hero, numerados del 1 al 4.
🎯 Mini reto

Sin mirar el paso siguiente: ¿en qué orden crees que deberían ir en el HTML los 4 .slide y el .hero-content para que el texto termine visible por encima de las imágenes? Ya lo escribiste arriba — solo confirma que entiendes por qué ese orden importa antes de seguir.

Paso 2 · Apilar las imágenes con position

Convertir los 4 divs en capas superpuestas

Ahora mismo los 4 .slide están apilados uno debajo del otro, como bloques normales. Para que ocupen el mismo lugar exacto, uno encima del otro, se usa position: absolute sobre un contenedor con position: relative.

Agrega esto en tu estilos.css
.hero {
  position: relative;
  height: 480px;
  overflow: hidden;
}

.slide {
  position: absolute;
  inset: 0;
  opacity: 0;
}
Línea por línea
.hero → position: relativeConvierte a .hero en el "punto de referencia" para cualquier hijo con position: absolute. Sin esta línea, los slides se posicionarían respecto a toda la página, no respecto al banner.
.hero → height: 480pxComo los slides estarán en absolute (y eso los saca del flujo normal), el .hero ya no crece automáticamente según su contenido — necesita una altura fija propia.
.hero → overflow: hiddenRecorta cualquier cosa que se salga de los límites del banner, evitando barras de scroll accidentales.
.slide → position: absoluteSaca a cada slide del flujo normal del documento y lo posiciona respecto al .hero (gracias al relative del paso anterior).
.slide → inset: 0Atajo que equivale a top:0; right:0; bottom:0; left:0; — estira cada slide para que cubra por completo los cuatro bordes del .hero.
.slide → opacity: 0Por defecto, las 4 capas están invisibles (transparencia total). Esto es intencional: en el paso 5, la animación se encargará de mostrarlas una por una.
Checkpoint visual
✅ Checkpoint
  • El banner ahora es un rectángulo de 480px de alto (probablemente gris o vacío, porque los slides no tienen ni color ni imagen todavía).
  • El texto (.hero-content) puede haberse "escondido" o mezclado — es normal, aún no le diste estilo; se resuelve en el paso 4.
  • Si inspeccionas el HTML en el navegador, los 4 .slide deberían tener el mismo tamaño y posición exacta, superpuestos.
🎯 Mini reto

Agrega temporalmente background: red; solo a .slide-1 y súbele la opacidad a opacity: 1; (solo a esa clase, no a .slide general). Deberías ver un rectángulo rojo del tamaño exacto del banner. Cuando lo confirmes, quítalo — era solo para comprobar que el posicionamiento funciona.

Paso 3 · Imágenes reales + overlay oscuro

Dar a cada capa su imagen de fondo

Cada .slide-N recibe una imagen distinta con background-image. También se agrega un degradado oscuro semitransparente encima de la imagen (con ::after), para que el texto blanco del paso 4 se lea bien sin importar qué tan clara sea la foto.

Agrega esto en tu estilos.css
.slide {
  background-size: cover;
  background-position: center;
}

.slide-1 { background-image: url("https://picsum.photos/id/1018/1400/600"); }
.slide-2 { background-image: url("https://picsum.photos/id/1015/1400/600"); }
.slide-3 { background-image: url("https://picsum.photos/id/1043/1400/600"); }
.slide-4 { background-image: url("https://picsum.photos/id/1050/1400/600"); }

.hero::after {
  content: "";
  position: absolute;
  inset: 0;
  background: linear-gradient(180deg, rgba(0,0,0,.25), rgba(0,0,0,.55));
}
Línea por línea
.slide → background-size: coverEscala la imagen para que cubra todo el espacio de la capa sin deformarse, recortando el exceso si su proporción no coincide exactamente con la del banner.
.slide → background-position: centerCuando se recorta la imagen, esto asegura que el recorte se haga desde el centro (no desde una esquina), manteniendo lo más importante de la foto visible.
.slide-1 → background-image: url(...)Asigna la imagen específica de esa capa. Cada slide-N apunta a una URL distinta — así cada capa termina mostrando una foto diferente.
.hero::after::after crea un elemento "fantasma" extra, generado por CSS, justo después del contenido real del .hero — sin tener que agregar un div más en el HTML.
content: ""Obligatorio para que un ::after exista visualmente. Puede ir vacío: aquí no necesitamos texto, solo la capa de color.
position: absolute; inset: 0;Igual que con los slides: estira este pseudo-elemento para cubrir todo el banner, encima de las imágenes (por estar declarado después en el HTML/CSS).
background: linear-gradient(...)Crea un degradado negro semitransparente: más claro arriba (.25 de opacidad) y más oscuro abajo (.55), donde normalmente va el texto.
Checkpoint visual
✅ Checkpoint
  • Deberías ver una imagen visible (la del slide que tenga opacity: 1 del reto anterior — si ya lo quitaste, quizás no veas ninguna todavía, y está bien).
  • Sobre la imagen se nota un oscurecimiento gradual de arriba hacia abajo.
  • Cambia temporalmente opacity: 1 en .slide-2, .slide-3 o .slide-4 para confirmar que cada una carga su propia imagen distinta.
🎯 Mini reto

Reemplaza al menos una de las 4 URLs por una imagen propia (puede ser un enlace directo a cualquier imagen tuya en internet) o cambia el número de id/XXXX/ de picsum.photos por otro que te guste. Después ajusta los dos valores de opacidad del linear-gradient (por ejemplo a .4 y .7) y observa cómo cambia el contraste.

Paso 4 · El texto sobre las imágenes

Centrar y estilizar el contenido del hero

El bloque .hero-content también se saca del flujo normal con position: absolute y se centra con Flexbox. Necesita z-index para asegurarnos de que quede por encima de las imágenes y del degradado.

Agrega esto en tu estilos.css
.hero-content {
  position: absolute;
  inset: 0;
  z-index: 2;
  display: flex;
  flex-direction: column;
  align-items: center;
  justify-content: center;
  text-align: center;
  color: white;
  padding: 0 24px;
}
.hero-content h1 { font-size: 2.4rem; margin-bottom: 12px; }
.hero-content p { font-size: 1.05rem; margin-bottom: 22px; max-width: 480px; }
.btn {
  background: #fb7185;
  color: white;
  padding: 12px 26px;
  border-radius: 999px;
  text-decoration: none;
  font-weight: 700;
}
Línea por línea
.hero-content → position: absolute; inset: 0;Mismo truco que con los slides: se estira para ocupar todo el banner y así poder centrar su contenido dentro de ese espacio completo.
z-index: 2Define el "orden de apilado". Los slides y el ::after no tienen z-index explícito (equivale a 0), así que este valor de 2 asegura que el texto quede visualmente por encima de todo.
display: flex; flex-direction: column;Convierte a .hero-content en un contenedor flex en columna, para apilar título → párrafo → botón verticalmente.
align-items: center; justify-content: center;Centra el contenido tanto horizontal (align-items, eje cruzado en modo columna) como verticalmente (justify-content, eje principal en modo columna) dentro del banner.
color: whiteEl texto necesita ser claro para leerse sobre fotos y el degradado oscuro del paso 3.
.hero-content p → max-width: 480pxEvita que el párrafo se estire de borde a borde en pantallas anchas — los textos cortos se leen mejor con un ancho limitado.
.btn → border-radius: 999pxUn valor tan alto redondea completamente los extremos del botón, dándole forma de "píldora".
Checkpoint visual
✅ Checkpoint
  • Ahora ves el título, el párrafo y el botón centrados sobre la imagen, legibles gracias al degradado oscuro.
  • El botón tiene forma de píldora y color de acento, distinto al resto del texto.
  • Si el texto no aparece, revisa que z-index: 2 esté puesto — sin eso, las capas de imagen podrían tapar el contenido.
🎯 Mini reto

Agrega una regla .btn:hover { } con un background distinto (por ejemplo un tono más oscuro de rosa) y una transition: background 0.2s ease; en .btn, para que el cambio de color al pasar el mouse sea suave en vez de instantáneo.

Paso 5 · La animación con @keyframes

Hacer que las imágenes roten solas

Este es el paso central. Se define una animación llamada fundido que hace que un elemento aparezca y desaparezca (fade in / fade out). Luego se aplica a las 4 capas con la misma animación pero un animation-delay distinto en cada una, para que no aparezcan todas al mismo tiempo.

Agrega esto en tu estilos.css
@keyframes fundido {
  0%   { opacity: 0; }
  5%   { opacity: 1; }
  20%  { opacity: 1; }
  25%  { opacity: 0; }
  100% { opacity: 0; }
}

.slide {
  animation: fundido 16s infinite;
}
.slide-1 { animation-delay: 0s;  }
.slide-2 { animation-delay: 4s;  }
.slide-3 { animation-delay: 8s;  }
.slide-4 { animation-delay: 12s; }
Línea por línea
@keyframes fundido { }Define una animación con nombre propio (fundido) que podrás reutilizar. Dentro se describe cómo cambia la opacity a lo largo del tiempo, en porcentajes de 0% (inicio) a 100% (fin del ciclo).
0% { opacity: 0; }Al empezar el ciclo, la capa está totalmente invisible.
5% { opacity: 1; }Muy rápido (en el primer 5% del tiempo total) pasa a estar completamente visible — esto crea el efecto de aparición suave (fade in), no un salto brusco.
20% { opacity: 1; }Se mantiene visible sin cambios desde el 5% hasta el 20% del ciclo — es el tiempo que la imagen se queda "quieta" en pantalla.
25% { opacity: 0; }Entre el 20% y el 25% se desvanece de nuevo (fade out).
100% { opacity: 0; }Se mantiene invisible el resto del ciclo (75% restante), mientras les toca el turno a las otras 3 capas.
.slide → animation: fundido 16s infinite;Aplica la animación fundido a las 4 capas por igual: dura 16s por ciclo completo y infinite hace que se repita para siempre.
.slide-1 → animation-delay: 0s;Retrasa el inicio de su propio ciclo de animación. Con 0s, el slide 1 empieza a animarse de inmediato: visible durante el primer 25% de 16s, es decir, los primeros 4 segundos.
.slide-2/3/4 → 4s, 8s, 12sCada capa arranca su ciclo 4 segundos después que la anterior. Como cada una solo es visible durante "su" primer 25% del ciclo, el resultado es que se turnan cada 4 segundos sin superponerse — 4 imágenes × 4s = 16s, el mismo total que la duración de la animación.
✅ Checkpoint
  • Sin necesidad de tocar ningún botón, el banner ahora cambia de imagen solo, cada 4 segundos, con un desvanecimiento suave (no un salto brusco).
  • Después de la cuarta imagen, vuelve a la primera y el ciclo se repite indefinidamente.
  • Si ves un "parpadeo" en vez de un fundido suave, revisa que hayas dejado los 5 puntos porcentuales de @keyframes exactamente como están arriba (0%, 5%, 20%, 25%, 100%).
🎯 Mini reto

Sin ver el resultado todavía: si quisieras que cada imagen se mostrara durante 5 segundos en vez de 4 (para un total de 20s con 4 imágenes), ¿qué valores cambiarías? Piensa la respuesta, luego pruébala: ajusta 16s a 20s en animation, y los delays a 0s, 5s, 10s, 15s.

Paso 6 · Responsive

Que se vea bien también en pantallas pequeñas

En celulares, un banner de 480px de alto con un título de 2.4rem se ve desproporcionado. Con una @media query se reduce la altura y el tamaño de fuente solo por debajo de cierto ancho de pantalla.

Agrega esto en tu estilos.css
/* pantallas de 600px o menos */
@media (max-width: 600px) {
  .hero { height: 340px; }
  .hero-content h1 { font-size: 1.5rem; }
  .hero-content p { font-size: .9rem; }
}
Línea por línea
@media (max-width: 600px) { }Todo lo declarado dentro de estas llaves solo se aplica cuando el ancho de la ventana es de 600px o menos — típico de un celular en vertical.
.hero → height: 340pxReduce la altura del banner de 480px a 340px, evitando que ocupe demasiada pantalla en un dispositivo pequeño.
.hero-content h1/p → font-size más chicoReduce el tamaño de letra del título y el párrafo para que quepan cómodamente en un banner más bajo y angosto.
✅ Checkpoint
  • Al achicar la ventana del navegador por debajo de 600px de ancho, el banner debería verse más bajo y el texto más pequeño, pero seguir siendo legible y bien centrado.
  • La animación de las imágenes debe seguir funcionando igual — el @media no toca nada relacionado con @keyframes ni animation.
🎯 Mini reto

Agrega una segunda @media (max-width: 380px) para celulares muy angostos, que reduzca aún más el padding horizontal de .hero-content (por ejemplo a 0 12px) para que el texto no quede pegado a los bordes.
