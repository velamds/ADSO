Antes de empezar

Esta guía asume que ya conoces getElementById, addEventListener, createElement, appendChild y textContent (si no, esos son los cinco ejercicios del nivel 1). Aquí subimos un poco el nivel: vamos a trabajar con varios elementos a la vez, a delegar eventos en un contenedor padre, a leer y escribir atributos, y a recorrer el árbol del DOM entre padres, hijos y hermanos.

🔒 El código sigue bloqueado para copiar y pegar. Transcríbelo a mano: en este nivel los detalles de sintaxis importan más (paréntesis, puntos, comillas), y escribirlos tú mismo ayuda a que se fijen.
Ejercicio 1

Seleccionar varios elementos con querySelectorAll

Hasta ahora seleccionabas un elemento a la vez con getElementById. Ahora usarás querySelectorAll para seleccionar todos los elementos que compartan una clase, y forEach para recorrerlos.

Demo en vivo

  • Lavar los platos
  • Estudiar JavaScript
  • Sacar la basura

HTML para transcribir

index.htmlHTML🔒
01<ul>
02  <li class="tarea">Lavar los platos</li>
03  <li class="tarea">Estudiar JavaScript</li>
04  <li class="tarea">Sacar la basura</li>
05</ul>
06<button id="btnMarcarTodas">Marcar todas como completadas</button>
02-04

Tres elementos <li> que comparten la misma clase tarea. A diferencia de un id, una class sí se puede repetir en varios elementos: por eso es la forma correcta de "agrupar" elementos similares.

06

Un botón para marcar todas las tareas de una vez.

CSS para transcribir

estilos.cssCSS🔒
01.tarea {
02  cursor: pointer;
03  padding: 8px;
04}
05
06.completada {
07  text-decoration: line-through;
08  color: #98a0b8;
09}
01-04

cursor: pointer hace que el mouse se vea como una manito al pasar sobre la tarea, indicando que se puede hacer clic.

06-09

.completada es, otra vez, una clase que no está en el HTML al inicio: JavaScript la agregará o quitará con classList.

JavaScript para transcribir

script.jsJavaScript🔒
01const tareas = document.querySelectorAll(".tarea");
02const btnMarcarTodas = document.getElementById("btnMarcarTodas");
03
04tareas.forEach(function (tarea) {
05  tarea.addEventListener("click", function () {
06    tarea.classList.toggle("completada");
07  });
08});
09
10btnMarcarTodas.addEventListener("click", function () {
11  tareas.forEach(function (tarea) {
12    tarea.classList.add("completada");
13  });
14});
01

document.querySelectorAll(".tarea") busca todos los elementos que tengan class="tarea" (el punto antes de "tarea" indica que es una clase, igual que en CSS) y devuelve una lista de ellos llamada NodeList, guardada en tareas.

02

El botón, seleccionado como siempre por su id único.

04

tareas.forEach(...) recorre la lista y ejecuta la función una vez por cada tarea, pasándola como parámetro (aquí llamado tarea).

05-07

Dentro del recorrido, a cada tarea se le agrega su propio addEventListener: al hacer clic en ella, alterna (agrega o quita) la clase completada solo sobre sí misma.

10-14

El botón "Marcar todas" vuelve a recorrer la misma lista tareas con forEach, pero esta vez usando classList.add (no toggle) para asegurarnos de que todas queden marcadas, sin importar su estado anterior.

💡 Dato importante: tareas es una foto fija de los elementos que existían en el momento en que se ejecutó querySelectorAll. Si más adelante agregas una nueva tarea al HTML con JavaScript, esa tarea nueva no tendrá el clic activado automáticamente, porque nunca fue parte de esa lista. Ese problema es justo lo que resuelve la delegación de eventos del siguiente ejercicio.

Ejercicio 2

Delegación de eventos

Vamos a construir una lista de productos donde cada uno tiene su botón de eliminar, pero en vez de agregar un addEventListener a cada botón, escucharemos los clics en el contenedor padre (<ul>). Así, incluso los productos agregados después seguirán funcionando.

Demo en vivo

    HTML para transcribir

    index.htmlHTML🔒
    01<input type="text" id="inputProducto" placeholder="Nuevo producto">
    02<button id="btnAgregarProducto">Agregar</button>
    03<ul id="listaProductos"></ul>
    01-03

    Un input, un botón y una lista vacía: la misma base de siempre. Lo distinto está en cómo vamos a escuchar los clics de los botones que se crearán adentro de la lista.

    JavaScript para transcribir

    script.jsJavaScript🔒
    01const inputProducto = document.getElementById("inputProducto");
    02const btnAgregar = document.getElementById("btnAgregarProducto");
    03const listaProductos = document.getElementById("listaProductos");
    04
    05btnAgregar.addEventListener("click", function () {
    06  const texto = inputProducto.value.trim();
    07  if (texto === "") return;
    08
    09  listaProductos.insertAdjacentHTML("beforeend", `<li>${texto} <button class="btn-borrar">Eliminar</button></li>`);
    10
    11  inputProducto.value = "";
    12});
    13
    14listaProductos.addEventListener("click", function (evento) {
    15  if (evento.target.classList.contains("btn-borrar")) {
    16    evento.target.closest("li").remove();
    17  }
    18});
    01-03

    Seleccionamos el input, el botón de agregar y la lista, como siempre.

    06

    Leemos el texto escrito y le quitamos espacios sobrantes con .trim().

    07

    Si quedó vacío, salimos de la función sin hacer nada más.

    09

    insertAdjacentHTML("beforeend", ...) es otra forma de agregar contenido, distinta de createElement + appendChild: le pasamos directamente un texto con HTML (usando comillas invertidas, o template literal) y lo inserta "justo antes de que termine" el elemento (beforeend significa eso). Aquí insertamos un <li> completo, con el texto del producto y su propio botón "Eliminar" ya incluido.

    11

    Limpiamos el campo de texto.

    14

    Aquí está la delegación: ponemos un único addEventListener en listaProductos (el <ul>, que siempre existe), en vez de uno por cada botón "Eliminar" (que se crean después y podrían no existir todavía cuando el script se ejecuta por primera vez).

    15

    evento.target es el elemento exacto donde ocurrió el clic. Como el <ul> puede recibir clics en cualquier parte de cualquier <li>, comprobamos si justo ese elemento tiene la clase btn-borrar, es decir, si el clic fue realmente sobre un botón de eliminar.

    16

    evento.target.closest("li") sube desde el botón hasta encontrar el <li> que lo contiene, y .remove() lo elimina completo de la página.

    💡 Compara con el Ejercicio 1: allí cada tarea ya existía en el HTML desde el principio, así que podíamos recorrerlas con forEach y ponerles su propio listener. Aquí los productos no existen todavía cuando carga la página, así que delegar el evento al contenedor padre es la única forma de que funcionen sin importar cuántos se agreguen después.
    🧩 Checkpoint 2

    ¿Por qué la delegación de eventos funciona incluso para productos agregados después de cargar la página?

    Ejercicio 3

    Atributos personalizados con dataset

    Vas a construir un selector de color: cada botón guarda su color en un atributo personalizado data-color, que JavaScript puede leer con dataset. También aprenderás a activar y quitar el atributo disabled con código.

    Demo en vivo

    Vista previa

    HTML para transcribir

    index.htmlHTML🔒
    01<div class="paleta">
    02  <button class="color-btn" data-color="#2451c4"></button>
    03  <button class="color-btn" data-color="#17a673"></button>
    04  <button class="color-btn" data-color="#d9782d"></button>
    05</div>
    06<div id="vistaPrevia" class="vista-previa">Vista previa</div>
    07<input type="checkbox" id="checkBloquear">
    02-04

    Cada botón tiene data-color="...". Cualquier atributo que empiece con data- es un atributo personalizado: no significa nada para el navegador, pero nosotros lo usamos para guardar información extra pegada al elemento.

    06

    Un recuadro que cambiará de color de fondo según el botón elegido.

    07

    Una casilla para bloquear/desbloquear la paleta completa.

    JavaScript para transcribir

    script.jsJavaScript🔒
    01const botonesColor = document.querySelectorAll(".color-btn");
    02const vistaPrevia = document.getElementById("vistaPrevia");
    03const checkBloquear = document.getElementById("checkBloquear");
    04
    05botonesColor.forEach(function (boton) {
    06  boton.style.backgroundColor = boton.dataset.color;
    07
    08  boton.addEventListener("click", function () {
    09    vistaPrevia.style.backgroundColor = boton.dataset.color;
    10  });
    11});
    12
    13checkBloquear.addEventListener("change", function () {
    14  botonesColor.forEach(function (boton) {
    15    if (checkBloquear.checked) {
    16      boton.setAttribute("disabled", "true");
    17    } else {
    18      boton.removeAttribute("disabled");
    19    }
    20  });
    21});
    01

    Seleccionamos todos los botones de color con querySelectorAll, igual que en el Ejercicio 1.

    02-03

    Seleccionamos la vista previa y la casilla de bloqueo por su id.

    06

    boton.dataset.color lee el valor del atributo data-color de ese botón. dataset es una forma abreviada: convierte automáticamente data-color en la propiedad .color. Usamos ese valor para pintar el propio botón al cargar la página, así el usuario ve el color antes de hacer clic.

    08-10

    Al hacer clic en un botón, tomamos su color guardado y lo aplicamos como fondo de la vista previa.

    13

    Escuchamos el evento "change" de la casilla: se dispara cada vez que se marca o desmarca.

    15-19

    checkBloquear.checked nos dice si la casilla está marcada (true) o no (false). Si está marcada, usamos setAttribute("disabled", "true") para deshabilitar cada botón; si no, usamos removeAttribute("disabled") para volver a habilitarlo. A diferencia de dataset (para atributos data-* personalizados), setAttribute/removeAttribute funcionan con cualquier atributo del HTML, incluidos los que el navegador sí interpreta, como disabled.

    🧩 Checkpoint 3

    ¿Cómo se lee desde JavaScript el valor del atributo data-color de un botón?

    Ejercicio 4

    Recorrer el DOM: padres, hijos y hermanos

    Construirás un acordeón de preguntas frecuentes. Al hacer clic en una pregunta, se muestra su respuesta usando nextElementSibling (el "hermano" siguiente en el HTML), y se cierran las demás respuestas abiertas.

    Demo en vivo

    Es la representación en memoria de la página que JavaScript puede leer y modificar.
    Una acción que ocurre en la página, como un clic, y que JavaScript puede "escuchar".
    Escuchar eventos en un elemento padre en vez de en cada hijo individual.

    HTML para transcribir

    index.htmlHTML🔒
    01<div class="faq-item">
    02  <button class="faq-pregunta">¿Qué es el DOM?</button>
    03  <div class="faq-respuesta">Es la representación en memoria de la página...</div>
    04</div>
    05
    06<div class="faq-item">
    07  <button class="faq-pregunta">¿Qué es un evento?</button>
    08  <div class="faq-respuesta">Una acción que ocurre en la página...</div>
    09</div>
    01-04

    Cada pregunta es un .faq-item que contiene exactamente dos elementos: el botón de la pregunta y, justo después, el <div> con la respuesta. Ese orden es clave para el paso siguiente.

    06-09

    El siguiente ítem del FAQ sigue la misma estructura: pregunta y respuesta como "hermanos" dentro del mismo contenedor.

    CSS para transcribir

    estilos.cssCSS🔒
    01.faq-respuesta {
    02  display: none;
    03}
    04
    05.faq-respuesta.mostrar {
    06  display: block;
    07}
    01-03

    Por defecto, todas las respuestas están ocultas con display: none.

    05-07

    .faq-respuesta.mostrar (sin espacio entre ambas clases) selecciona un elemento que tenga ambas clases a la vez. Cuando JavaScript agregue la clase mostrar a una respuesta, esta regla la vuelve visible.

    JavaScript para transcribir

    script.jsJavaScript🔒
    01const preguntas = document.querySelectorAll(".faq-pregunta");
    02
    03preguntas.forEach(function (pregunta) {
    04  pregunta.addEventListener("click", function () {
    05    const respuestaActual = pregunta.nextElementSibling;
    06    const yaAbierta = respuestaActual.classList.contains("mostrar");
    07
    08    preguntas.forEach(function (otraPregunta) {
    09      otraPregunta.nextElementSibling.classList.remove("mostrar");
    10    });
    11
    12    if (!yaAbierta) {
    13      respuestaActual.classList.add("mostrar");
    14    }
    15  });
    16});
    01

    Seleccionamos todos los botones de pregunta.

    03-04

    Recorremos cada pregunta y le agregamos su propio listener de clic (aquí sí podemos hacerlo así porque las preguntas ya existen desde el inicio, como en el Ejercicio 1).

    05

    pregunta.nextElementSibling es el elemento que está justo después de pregunta dentro del mismo padre, ignorando espacios en blanco. Como en el HTML la respuesta siempre va inmediatamente después de su pregunta, esto nos da exactamente el <div> de la respuesta correspondiente.

    06

    Antes de cambiar nada, guardamos si esa respuesta ya estaba abierta (yaAbierta), para decidir después si debemos volver a abrirla o dejarla cerrada.

    08-10

    Recorremos todas las preguntas y a la respuesta de cada una (usando de nuevo nextElementSibling) le quitamos la clase mostrar. Esto cierra todas las respuestas, incluida la que se acaba de clicar.

    12-14

    Si la respuesta que se clicó no estaba abierta antes (!yaAbierta), la volvemos a abrir agregándole la clase mostrar. Si sí estaba abierta, no hacemos nada más y se queda cerrada: así el mismo clic sirve para abrir y para cerrar.

    🧩 Checkpoint 4

    ¿Por qué el código guarda el valor de yaAbierta ANTES de cerrar todas las respuestas?

    Ejercicio 5

    Buscador en vivo (filtro de lista)

    El ejercicio más completo de este nivel: una lista se filtra en tiempo real mientras el usuario escribe, combinando el evento input, querySelectorAll, texto en minúsculas y mostrar/ocultar elementos con style.display.

    Demo en vivo

    • Manzana
    • Banano
    • Fresa
    • Uva
    • Mango

    HTML para transcribir

    index.htmlHTML🔒
    01<input type="text" id="buscador" placeholder="Buscar fruta...">
    02<ul id="listaBuscable">
    03  <li>Manzana</li>
    04  <li>Banano</li>
    05  <li>Fresa</li>
    06  <li>Uva</li>
    07  <li>Mango</li>
    08</ul>
    01

    El campo donde el usuario escribirá su búsqueda.

    02-08

    Una lista fija de frutas, ya presente en el HTML desde el inicio (no se crean con JavaScript en este ejercicio).

    JavaScript para transcribir

    script.jsJavaScript🔒
    01const buscador = document.getElementById("buscador");
    02const items = document.querySelectorAll("#listaBuscable li");
    03
    04buscador.addEventListener("input", function () {
    05  const texto = buscador.value.toLowerCase();
    06
    07  items.forEach(function (item) {
    08    const contenido = item.textContent.toLowerCase();
    09    const coincide = contenido.includes(texto);
    10
    11    item.style.display = coincide ? "list-item" : "none";
    12  });
    13});
    01

    Seleccionamos el campo de búsqueda.

    02

    "#listaBuscable li" es un selector CSS compuesto: significa "todos los <li> que estén dentro del elemento con id listaBuscable". Guardamos esa lista completa de frutas en items.

    04

    Usamos el evento "input", no "change": input se dispara con cada tecla que el usuario presiona, mientras que change solo se dispara cuando el campo pierde el foco. Para un filtro en vivo necesitamos reaccionar en cada tecla.

    05

    Convertimos lo que escribió el usuario a minúsculas con toLowerCase(), para que la búsqueda no distinga entre mayúsculas y minúsculas (que "uva" también encuentre "Uva").

    07

    Recorremos cada fruta de la lista para decidir, una por una, si debe mostrarse u ocultarse.

    08

    Tomamos el texto de esa fruta y también lo pasamos a minúsculas, para comparar en igualdad de condiciones.

    09

    contenido.includes(texto) devuelve true si contenido contiene en algún punto el texto buscado (por ejemplo, "mango".includes("man") es true).

    11

    Esta línea usa un operador ternario: es una forma corta de escribir un if/else en una sola línea. Se lee así: "si coincide es verdadero, usa 'list-item'; si no, usa 'none'". El resultado se asigna directamente a item.style.display, mostrando u ocultando la fruta según si coincide con la búsqueda.

    🧩 Checkpoint 5

    ¿Por qué este ejercicio usa el evento "input" en vez de "change" para el buscador?
