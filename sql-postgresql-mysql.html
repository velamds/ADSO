0Antes de empezar

Qué vas a aprender, qué instalar y cómo se lee esta guía con dos motores.

Esta guía enseña SQL desde cero con dos motores a la vez: PostgreSQL y MySQL. Casi todo el lenguaje es igual en ambos, así que la mayoría de los ejemplos se muestran una sola vez. Cuando una instrucción cambia, verás los dos dialectos lado a lado, cada uno con su color.

PostgreSQL

Muy fiel al estándar SQL, con tipos ricos (arreglos, JSONB, rangos) y transacciones muy estrictas. Se usa mucho en análisis y aplicaciones con reglas de negocio complejas.

MySQL

Sencillo de instalar y muy extendido en aplicaciones web (WordPress, tiendas en línea, la mayoría de hostings). MariaDB es un derivado casi idéntico.

Usa el selector fijo de la parte superior para ver solo PostgreSQL, solo MySQL o Ambos. Tu elección se recuerda al volver a abrir la página.

Qué necesitas

  • PostgreSQL 14 o superior, o MySQL 8.0 o superior. Las funciones de ventana, las expresiones WITH y las restricciones CHECK que usamos requieren MySQL 8.
  • Un cliente: la línea de comandos (psql o mysql) o una herramienta gráfica como DBeaver, pgAdmin o MySQL Workbench.
  • Entre 3 y 5 horas para leer, probar los ejemplos y resolver los 20 ejercicios finales.

Conectarse y moverse

PostgreSQL
psql -U postgres            # entrar al servidor
CREATE DATABASE tienda;
\c tienda                  # conectarse a la base
\l                         # listar bases de datos
\dt                        # listar tablas
\d producto                # describir una tabla
\q                         # salir
MySQL
mysql -u root -p           # entrar al servidor
CREATE DATABASE tienda CHARACTER SET utf8mb4;
USE tienda;
SHOW DATABASES;            -- listar bases de datos
SHOW TABLES;               -- listar tablas
DESCRIBE producto;         -- describir una tabla
exit

Los comandos que empiezan por \ en psql son del cliente, no son SQL. En MySQL, USE, SHOW y DESCRIBE sí se envían al servidor.

Reglas de escritura que verás en todo el texto

  • Cada sentencia termina con punto y coma ;.
  • Las palabras reservadas se escriben en mayúsculas por costumbre (SELECT, FROM). SQL no distingue mayúsculas en ellas; es solo legibilidad.
  • Los textos van entre comillas simples: 'Bogotá'. Las comillas dobles sirven para nombres de columnas en PostgreSQL y dan problemas en MySQL, así que no las uses para textos.
  • Los comentarios son -- hasta el final de la línea (en MySQL debe haber un espacio después de los dos guiones) y /* en bloque */.
  • Los nombres de tablas y columnas se escriben en minúscula con guion bajo (fecha_registro).

1Fundamentos de SQL

Qué es SQL, cómo se organiza y qué tipos de dato usarás.

SQL (Structured Query Language) es el lenguaje con el que se pide información a una base de datos relacional y se modifican sus datos. Es declarativo: dices qué resultado quieres y el motor decide cómo obtenerlo.

Una consulta se parece a una frase en inglés: «selecciona estas columnas, de esta tabla, donde se cumpla esta condición».

SELECT nombre, ciudad
FROM cliente
WHERE ciudad = 'Bogotá';

NULL: la ausencia de valor

NULL significa «no hay dato» (se desconoce o no aplica). No es cero ni texto vacío. Casi cualquier operación con NULL da NULL, y por eso se compara con IS NULL y no con =. Lo veremos en el capítulo 4.

2La base de ejemplo: una tienda

Crea las tablas y los datos con los que practicarás en todos los capítulos.

Todos los ejemplos y ejercicios usan la misma base: una tienda de tecnología con clientes, productos, pedidos y empleados. Créala una vez y úsala hasta el final.

El modelo

  • Una categoría agrupa varios productos.
  • Un cliente hace varios pedidos; cada pedido incluye varios productos, y esa relación muchos a muchos se guarda en detalle_pedido con la cantidad y el precio del momento.
  • Un empleado puede tener un jefe, que también es un empleado.

2. Crear las tablas

La única diferencia está en la columna numérica que se genera sola: GENERATED ALWAYS AS IDENTITY en PostgreSQL y AUTO_INCREMENT en MySQL.

PostgreSQL
CREATE TABLE categoria (
  id_categoria INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nombre       VARCHAR(60) NOT NULL UNIQUE
);

CREATE TABLE producto (
  id_producto  INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nombre       VARCHAR(100) NOT NULL,
  id_categoria INT NOT NULL REFERENCES categoria(id_categoria),
  precio       DECIMAL(12,2) NOT NULL CHECK (precio > 0),
  stock        INT NOT NULL DEFAULT 0 CHECK (stock >= 0)
);

CREATE TABLE cliente (
  id_cliente     INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nombre         VARCHAR(100) NOT NULL,
  correo         VARCHAR(150) NOT NULL UNIQUE,
  ciudad         VARCHAR(80),
  fecha_registro DATE NOT NULL
);

CREATE TABLE pedido (
  id_pedido  INT PRIMARY KEY,
  id_cliente INT NOT NULL REFERENCES cliente(id_cliente),
  fecha      DATE NOT NULL,
  estado     VARCHAR(15) NOT NULL
             CHECK (estado IN ('pendiente','pagado','enviado','entregado','cancelado'))
);

CREATE TABLE detalle_pedido (
  id_pedido       INT REFERENCES pedido(id_pedido),
  id_producto     INT REFERENCES producto(id_producto),
  cantidad        INT NOT NULL CHECK (cantidad > 0),
  precio_unitario DECIMAL(12,2) NOT NULL,
  PRIMARY KEY (id_pedido, id_producto)
);

CREATE TABLE empleado (
  id_empleado INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nombre      VARCHAR(100) NOT NULL,
  cargo       VARCHAR(60) NOT NULL,
  salario     DECIMAL(12,2) NOT NULL,
  id_jefe     INT REFERENCES empleado(id_empleado)
);
MySQL
CREATE TABLE categoria (
  id_categoria INT AUTO_INCREMENT PRIMARY KEY,
  nombre       VARCHAR(60) NOT NULL UNIQUE
);

CREATE TABLE producto (
  id_producto  INT AUTO_INCREMENT PRIMARY KEY,
  nombre       VARCHAR(100) NOT NULL,
  id_categoria INT NOT NULL REFERENCES categoria(id_categoria),
  precio       DECIMAL(12,2) NOT NULL CHECK (precio > 0),
  stock        INT NOT NULL DEFAULT 0 CHECK (stock >= 0)
);

CREATE TABLE cliente (
  id_cliente     INT AUTO_INCREMENT PRIMARY KEY,
  nombre         VARCHAR(100) NOT NULL,
  correo         VARCHAR(150) NOT NULL UNIQUE,
  ciudad         VARCHAR(80),
  fecha_registro DATE NOT NULL
);

CREATE TABLE pedido (
  id_pedido  INT PRIMARY KEY,
  id_cliente INT NOT NULL REFERENCES cliente(id_cliente),
  fecha      DATE NOT NULL,
  estado     VARCHAR(15) NOT NULL
             CHECK (estado IN ('pendiente','pagado','enviado','entregado','cancelado'))
);

CREATE TABLE detalle_pedido (
  id_pedido       INT REFERENCES pedido(id_pedido),
  id_producto     INT REFERENCES producto(id_producto),
  cantidad        INT NOT NULL CHECK (cantidad > 0),
  precio_unitario DECIMAL(12,2) NOT NULL,
  PRIMARY KEY (id_pedido, id_producto)
);

CREATE TABLE empleado (
  id_empleado INT AUTO_INCREMENT PRIMARY KEY,
  nombre      VARCHAR(100) NOT NULL,
  cargo       VARCHAR(60) NOT NULL,
  salario     DECIMAL(12,2) NOT NULL,
  id_jefe     INT REFERENCES empleado(id_empleado)
);

Mayúsculas y minúsculas

En MySQL, LIKE ignora las mayúsculas con la configuración habitual. En PostgreSQL LIKE las distingue: 'port%' no encuentra «Portátil». Para ignorarlas usa ILIKE, que solo existe en PostgreSQL.

PostgreSQL
SELECT nombre
FROM producto
WHERE nombre ILIKE '%bluetooth%';
MySQL
SELECT nombre
FROM producto
WHERE nombre LIKE '%bluetooth%';
Resultado · 1 fila
nombre
Parlante Bluetooth

Para una versión que funciona igual en ambos: WHERE LOWER(nombre) LIKE '%bluetooth%'.

Lógica de tres valores

Una condición puede ser verdadera, falsa o desconocida. WHERE solo deja pasar las verdaderas. Por eso WHERE id_jefe = NULL nunca devuelve nada, y WHERE id_jefe <> 2 tampoco devuelve las filas con id_jefe nulo.

Orden de lectura de una consulta

Aunque escribes SELECT primero, el motor evalúa en este orden. Te ayudará a entender los errores más adelante:

  1. FROM y JOIN: de dónde salen las filas.
  2. WHERE: qué filas se conservan.
  3. GROUP BY: se agrupan.
  4. HAVING: qué grupos se conservan.
  5. SELECT: se calculan las columnas y los alias.
  6. ORDER BY, luego LIMIT.

Por eso el alias que defines en SELECT no se puede usar en WHERE, pero sí en ORDER BY.

5Expresiones y funciones

Calcular, transformar texto, usar fechas y tomar decisiones dentro de la consulta.

Aritmética

Se usan + - * / y % (resto). Con ellos se calculan columnas derivadas. La división tiene una diferencia importante:

PostgreSQL
SELECT 7 / 2   AS entera,      -- 3
       7 / 2.0 AS decimal,    -- 3.5000000000000000
       7 % 2   AS resto;      -- 1
MySQL
SELECT 7 / 2     AS decimal,   -- 3.5000
       7 DIV 2   AS entera,    -- 3
       7 % 2     AS resto;     -- 1

En PostgreSQL, dividir dos enteros da un entero. En MySQL, / siempre da decimal y para la división entera se usa DIV.

Hasta aquí solo leímos datos. Las sentencias DML (Data Manipulation Language) los modifican. Estos ejemplos no devuelven una tabla: el motor responde con el número de filas afectadas (INSERT 0 1, Query OK, 1 row affected).

Siempre nombra las columnas

12Transacciones y concurrencia

COMMIT, ROLLBACK, ACID, niveles de aislamiento y bloqueos.

Una transacción agrupa varias sentencias en una unidad indivisible: o se aplican todas, o ninguna. El ejemplo clásico es una transferencia bancaria: restar de una cuenta y sumar en otra. Si falla a la mitad, no puede quedar dinero «en el aire».

Propiedades ACID

LetraPropiedadSignificado
AAtomicidadTodo o nada
CConsistenciaLos datos pasan de un estado válido a otro válido (se respetan las restricciones)
IAislamientoLas transacciones simultáneas no se estorban entre sí
DDurabilidadLo confirmado sobrevive a una caída del servidor

Comandos

PostgreSQL
BEGIN;

UPDATE producto SET stock = stock - 1 WHERE id_producto = 1;
INSERT INTO detalle_pedido (id_pedido, id_producto, cantidad, precio_unitario)
VALUES (5006, 1, 1, 3200000);

COMMIT;      -- confirma
-- ROLLBACK; -- o deshace todo
MySQL
START TRANSACTION;

UPDATE producto SET stock = stock - 1 WHERE id_producto = 1;
INSERT INTO detalle_pedido (id_pedido, id_producto, cantidad, precio_unitario)
VALUES (5006, 1, 1, 3200000);

COMMIT;      -- confirma
-- ROLLBACK; -- o deshace todo

Fuera de una transacción explícita, ambos motores usan autocommit: cada sentencia se confirma sola al ejecutarse. En MySQL solo las tablas InnoDB (el motor por defecto) soportan transacciones.

SAVEPOINT: deshacer una parte

BEGIN;  -- en MySQL: START TRANSACTION;

INSERT INTO categoria (nombre) VALUES ('Prueba A');
SAVEPOINT despues_a;

INSERT INTO categoria (nombre) VALUES ('Prueba B');
ROLLBACK TO SAVEPOINT despues_a;   -- descarta solo «Prueba B»

COMMIT;                            -- queda «Prueba A»
Prueba el cambio antes de confirmar

Un hábito seguro para UPDATE y DELETE: abre la transacción, ejecuta el cambio, verifica con un SELECT que el número de filas es el esperado y solo entonces haz COMMIT. Si algo salió mal, ROLLBACK.

Diferencia importante: DDL dentro de transacciones

En PostgreSQL, casi todo el DDL (CREATE TABLE, ALTER TABLE…) es transaccional: puedes probar una migración y revertirla. En MySQL, el DDL provoca un commit implícito: lo que hubiera pendiente se confirma y el DDL no se puede deshacer.

Aislamiento: qué ve una transacción de las demás

Cuando dos transacciones trabajan a la vez pueden aparecer anomalías:

  • Lectura sucia: ver datos de otra transacción aún sin confirmar.
  • Lectura no repetible: leer la misma fila dos veces y obtener valores distintos porque otra transacción la cambió y confirmó.
  • Lectura fantasma: repetir una consulta y que aparezcan filas nuevas.

Bloqueos: reservar filas

Para evitar que dos clientes compren la última unidad a la vez, se bloquea la fila mientras se decide:

BEGIN;  -- START TRANSACTION en MySQL

SELECT stock FROM producto WHERE id_producto = 1 FOR UPDATE;
-- otras transacciones que quieran modificar esta fila esperan

UPDATE producto SET stock = stock - 1 WHERE id_producto = 1;
COMMIT;
Deadlock

Si la transacción A espera una fila que tiene B y B espera una de A, ninguna avanza: el motor detecta el deadlock y cancela una de las dos con un error. La defensa es tocar las filas siempre en el mismo orden y mantener las transacciones cortas.

13Índices y rendimiento

Qué es un índice, cómo leer EXPLAIN y qué evitar.

Con pocas filas todo es rápido. Con millones, una consulta mal pensada tarda minutos. Las herramientas básicas son los índices y leer el plan de ejecución.

Índices

Un índice es una estructura auxiliar (normalmente un árbol B) que permite encontrar filas sin leer toda la tabla, como el índice alfabético de un libro. Las claves primarias y las restricciones UNIQUE ya crean uno automáticamente.

-- Acelera: WHERE id_cliente = ... y los JOIN por id_cliente
CREATE INDEX idx_pedido_cliente ON pedido (id_cliente);

-- Índice compuesto: sirve para filtrar por estado, o por estado y fecha
CREATE INDEX idx_pedido_estado_fecha ON pedido (estado, fecha);

-- Índice único
CREATE UNIQUE INDEX uq_cliente_correo ON cliente (correo);

15Seguridad, buenas prácticas y errores comunes

Consultas parametrizadas, permisos y una lista para depurar.

Seguridad

Inyección SQL. Ocurre cuando una aplicación arma la consulta pegando texto del usuario. Si el usuario escribe ' OR '1'='1, cambia el significado de la consulta.

-- MAL: se concatena la entrada del usuario
consulta = "SELECT * FROM cliente WHERE correo = '" + entrada + "'"

-- BIEN: consulta parametrizada; el motor trata el valor siempre como dato
SELECT * FROM cliente WHERE correo = $1;   -- PostgreSQL
SELECT * FROM cliente WHERE correo = ?;    -- MySQL

Permisos (DCL). Cada aplicación debe conectarse con un usuario con lo mínimo necesario.

PostgreSQL
CREATE ROLE app_ventas LOGIN PASSWORD 'cambia_esta_clave';
GRANT SELECT, INSERT, UPDATE ON pedido, detalle_pedido TO app_ventas;
GRANT SELECT ON cliente, producto TO app_ventas;
REVOKE UPDATE ON pedido FROM app_ventas;
MySQL
CREATE USER 'app_ventas'@'%' IDENTIFIED BY 'cambia_esta_clave';
GRANT SELECT, INSERT, UPDATE ON tienda.pedido TO 'app_ventas'@'%';
GRANT SELECT ON tienda.cliente TO 'app_ventas'@'%';
REVOKE UPDATE ON tienda.pedido FROM 'app_ventas'@'%';

Buenas prácticas de escritura

  • Escribe las palabras clave en mayúscula y cada cláusula principal en una línea nueva.
  • Usa nombres claros y consistentes: minúsculas con guion bajo, tablas en singular, claves id_tabla.
  • Siempre alias de tabla cortos y significativos al unir varias tablas; califica todas las columnas.
  • Prefiere JOIN … ON explícito en vez de listar tablas con comas y condiciones en WHERE.
  • No uses SELECT * salvo para explorar.
  • Comenta lo no obvio con --.
  • Haz respaldos y prueba que se puedan restaurar.
  • Prueba UPDATE/DELETE primero como SELECT, y en una transacción.
