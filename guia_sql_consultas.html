1SELECT — Seleccionar columnas

El comando SELECT es el más fundamental de SQL. Lee datos sin modificarlos.

Sintaxis básica

SintaxisSELECT
SELECT columna1, columna2, ...
FROM   nombre_tabla;
1

Seleccionar todas las columnas con *

Usa * para traer todas las columnas. Evítalo en producción — es mejor ser explícito.

2

Nombrar columnas (alias)

Con AS renombras una columna en el resultado.

3

Expresiones calculadas

Puedes hacer cálculos directamente en el SELECT.

4

Ejemplo 1.1 — SELECT *SELECT

2WHERE — Filtrar filas

La cláusula WHERE filtra qué filas incluye el resultado. Solo pasan las filas donde la condición es TRUE.

Operadores de comparación

Operadores disponiblesWHERE
columna =   'valor'   -- igual
columna <>  'valor'   -- diferente (también !=)
columna >   100       -- mayor que
columna >=  100       -- mayor o igual
columna <   100       -- menor que
columna BETWEEN 100 AND 500
columna IN ('a', 'b', 'c')
columna LIKE 'patrón%'
columna IS NULL
columna IS NOT NULL
Ejemplo 2.1 — Comparaciones simplesWHERE
-- Productos con precio mayor a 5000
SELECT nombre, marca, precio_venta
FROM   productos
WHERE  precio_venta > 5000
ORDER BY precio_venta DESC;

-- Clientes del tipo 'vip'
SELECT nombre, apellido, ciudad, tipo_cliente
FROM   clientes
WHERE  tipo_cliente = 'vip';
Ejemplo 2.2 — BETWEEN, IN, LIKEWHERE
-- Pedidos con total entre 1000 y 10000
SELECT pedido_id, fecha_pedido, total, estado
FROM   pedidos
WHERE  total BETWEEN 1000 AND 10000;

-- Pedidos con estado 'entregado' o 'enviado'
SELECT pedido_id, estado, total
FROM   pedidos
WHERE  estado IN ('entregado', 'enviado');

-- Productos cuyo nombre empieza con 'Samsung'
SELECT nombre, precio_venta, stock
FROM   productos
WHERE  nombre LIKE 'Samsung%';

-- Empleados cuyo apellido contiene 'García'
SELECT nombre, apellido, puesto
FROM   empleados
WHERE  apellido LIKE '%García%';
Ejemplo 2.3 — AND, OR, NOTWHERE
-- Productos Apple con precio mayor a 10000 y con stock disponible
SELECT nombre, precio_venta, stock
FROM   productos
WHERE  marca = 'Apple'
  AND  precio_venta > 10000
  AND  stock > 0;

-- Clientes de CDMX o Guadalajara
SELECT nombre, apellido, ciudad
FROM   clientes
WHERE  ciudad = 'Ciudad de México'
   OR  ciudad = 'Guadalajara';

-- Productos activos, no Samsung, precio menor a 3000
SELECT nombre, marca, precio_venta
FROM   productos
WHERE  activo = TRUE
  AND NOT marca = 'Samsung'
  AND  precio_venta < 3000;
⚠️
Precaución con NULL: columna = NULL nunca es TRUE. Siempre usa IS NULL o IS NOT NULL. Por ejemplo: WHERE jefe_id IS NULL para empleados sin jefe.

3ORDER BY — Ordenar resultados

Sin ORDER BY, el motor de base de datos puede devolver filas en cualquier orden. Usa esta cláusula para controlar el orden.

Ejemplo 3.1 — Orden simpleORDER BY
-- Productos ordenados por precio, más caro primero
SELECT nombre, marca, precio_venta
FROM   productos
ORDER BY precio_venta DESC;

-- Clientes ordenados por apellido alfabéticamente
SELECT nombre, apellido, ciudad
FROM   clientes
ORDER BY apellido ASC, nombre ASC;
Ejemplo 3.2 — Orden múltiple y por expresiónORDER BY
-- Empleados ordenados por departamento y luego por salario desc
SELECT nombre, apellido, departamento_id, salario
FROM   empleados
ORDER BY departamento_id ASC,
         salario DESC;

-- Productos por margen calculado (puedes ordenar por alias o posición)
SELECT
    nombre,
    precio_venta - precio_compra AS margen
FROM  productos
ORDER BY margen DESC;

4LIMIT y OFFSET — Paginación

LIMIT restringe cuántas filas se devuelven. OFFSET salta las primeras n filas — útil para paginación.

Ejemplo 4.1 — Top NLIMIT
-- Top 10 productos más caros
SELECT nombre, marca, precio_venta
FROM   productos
ORDER BY precio_venta DESC
LIMIT  10;

-- Top 5 pedidos de mayor valor
SELECT pedido_id, cliente_id, total, fecha_pedido
FROM   pedidos
ORDER BY total DESC
LIMIT  5;
Ejemplo 4.2 — Paginación con OFFSETLIMIT
-- Página 1 (registros 1-20)
SELECT cliente_id, nombre, ciudad
FROM   clientes
ORDER BY cliente_id
LIMIT  20 OFFSET 0;

-- Página 2 (registros 21-40)
SELECT cliente_id, nombre, ciudad
FROM   clientes
ORDER BY cliente_id
LIMIT  20 OFFSET 20;

-- Fórmula: OFFSET = (página - 1) * tamaño_página

6GROUP BY — Agrupar resultados

GROUP BY divide las filas en grupos según el valor de una columna, y aplica las funciones de agregación a cada grupo.

💡
Regla clave: Toda columna en el SELECT que NO sea una función de agregación DEBE aparecer en el GROUP BY.
Ejemplo 6.1 — Ventas por estado de pedidoGROUP BY
SELECT
    estado,
    COUNT(*)                   AS cantidad,
    SUM(total)                 AS total_ventas,
    ROUND(AVG(total), 2)      AS promedio
FROM   pedidos
GROUP BY estado
ORDER BY total_ventas DESC;

Ejemplo 6.2 — Ventas por mes y añoGROUP BY
-- En SQLite usa strftime; en PostgreSQL usa DATE_TRUNC o EXTRACT
SELECT
    strftime('%Y', fecha_pedido)  AS anio,
    strftime('%m', fecha_pedido) AS mes,

7HAVING — Filtrar grupos

HAVING es como WHERE pero actúa sobre grupos ya calculados. Se evalúa después del GROUP BY.

✅
WHERE vs HAVING: WHERE filtra filas individuales (antes de agrupar). HAVING filtra grupos (después de agrupar). Usa WHERE cuando puedas — es más eficiente.
Ejemplo 7.1 — Categorías con más de 20 productosHAVING
SELECT
    categoria_id,
    COUNT(*) AS num_productos
FROM   productos
WHERE  activo = TRUE
GROUP BY categoria_id
HAVING   COUNT(*) > 20
ORDER BY num_productos DESC;
Ejemplo 7.2 — Clientes con más de 5 pedidosHAVING
SELECT
    cliente_id,
    COUNT(*)    AS num_pedidos,
    SUM(total) AS total_gastado
FROM   pedidos
WHERE  estado <> 'cancelado'
GROUP BY cliente_id
HAVING   COUNT(*) >= 5
ORDER BY total_gastado DESC
LIMIT    15;

8JOINs — Combinar tablas

Los JOINs permiten combinar datos de múltiples tablas usando una columna en común.

8aINNER JOIN

Solo devuelve filas donde existe coincidencia en ambas tablas.

Ejemplo 8.1 — Productos con su categoríaINNER JOIN
SELECT
    p.producto_id,
    p.nombre        AS producto,
    p.marca,
    c.nombre        AS categoria,
    p.precio_venta
FROM        productos   p
INNER JOIN  categorias  c ON p.categoria_id = c.categoria_id
WHERE       c.nombre = 'Smartphones'
ORDER BY    p.precio_venta DESC;
Ejemplo 8.2 — Pedidos con cliente y empleadoINNER JOIN
SELECT
    pe.pedido_id,
    pe.fecha_pedido,
    cl.nombre  || ' ' || cl.apellido   AS cliente,
    em.nombre  || ' ' || em.apellido   AS vendedor,
    pe.total,
    pe.estado
FROM        pedidos   pe
INNER JOIN  clientes  cl  ON pe.cliente_id  = cl.cliente_id
INNER JOIN  empleados em  ON pe.empleado_id = em.empleado_id
WHERE       pe.estado = 'entregado'
ORDER BY    pe.total DESC
LIMIT       10;
Ejemplo 8.3 — Detalle completo de un pedido (JOIN múltiple)INNER JOIN
SELECT
    dp.pedido_id,
    pr.nombre         AS producto,
    cat.nombre        AS categoria,
    dp.cantidad,
    dp.precio_unitario,
    dp.cantidad * dp.precio_unitario  AS subtotal
FROM        detalle_pedidos  dp
INNER JOIN  productos        pr   ON dp.producto_id  = pr.producto_id
INNER JOIN  categorias       cat  ON pr.categoria_id = cat.categoria_id
WHERE       dp.pedido_id = 1;

8bLEFT JOIN / RIGHT JOIN

LEFT JOIN devuelve todas las filas de la tabla izquierda, y solo las coincidentes de la derecha (rellena con NULL si no hay match).

Ejemplo 8.4 — Clientes sin pedidosLEFT JOIN
-- Todos los clientes, con o sin pedidos
SELECT
    cl.cliente_id,
    cl.nombre     || ' ' || cl.apellido  AS cliente,
    COUNT(pe.pedido_id)   AS num_pedidos,
    COALESCE(SUM(pe.total), 0) AS total_gastado
FROM       clientes  cl
LEFT JOIN  pedidos   pe  ON cl.cliente_id = pe.cliente_id
GROUP BY   cl.cliente_id, cl.nombre, cl.apellido
ORDER BY   num_pedidos ASC;

-- Solo clientes que NUNCA compraron:
SELECT cl.*
FROM      clientes cl
LEFT JOIN pedidos  pe ON cl.cliente_id = pe.cliente_id
WHERE     pe.pedido_id IS NULL;

8cFULL OUTER JOIN

Devuelve todas las filas de ambas tablas, con NULL donde no hay coincidencia. SQLite no lo soporta nativamente — simúlalo con UNION.

Ejemplo 8.5 — FULL OUTER (PostgreSQL / simulado SQLite)FULL OUTER
-- PostgreSQL directo:
SELECT c.nombre, d.nombre AS departamento
FROM            categorias    c
FULL OUTER JOIN departamentos d ON c.categoria_id = d.departamento_id;

-- SQLite — simular con LEFT UNION RIGHT:
SELECT cl.cliente_id, cl.nombre, pe.pedido_id
FROM       clientes cl  LEFT JOIN  pedidos pe ON cl.cliente_id = pe.cliente_id
UNION
SELECT cl.cliente_id, cl.nombre, pe.pedido_id
FROM       pedidos  pe  LEFT JOIN  clientes cl ON pe.cliente_id = cl.cliente_id;

8dSELF JOIN

Unir una tabla consigo misma. Útil para relaciones jerárquicas como empleado-jefe.

Ejemplo 8.6 — Empleado y su jefe directoSELF JOIN
SELECT
    e.empleado_id,
    e.nombre   || ' ' || e.apellido  AS empleado,
    e.puesto,
    j.nombre   || ' ' || j.apellido  AS jefe
FROM       empleados e
LEFT JOIN  empleados j  ON e.jefe_id = j.empleado_id
ORDER BY  e.departamento_id, e.salario DESC;

9Subconsultas

Una subconsulta es una consulta dentro de otra. Puede ir en el SELECT, FROM, WHERE o HAVING.

Ejemplo 9.1 — Subconsulta en WHERESUBQUERY
-- Productos con precio mayor al promedio de su categoría
SELECT p1.nombre, p1.precio_venta, p1.categoria_id
FROM  productos p1
WHERE p1.precio_venta > (
    SELECT AVG(p2.precio_venta)
    FROM  productos p2
    WHERE p2.categoria_id = p1.categoria_id
);

-- Clientes que han gastado más que el promedio
SELECT cliente_id, SUM(total) AS gastado
FROM   pedidos
GROUP BY cliente_id
HAVING SUM(total) > (
    SELECT AVG(total_por_cliente)
    FROM (
        SELECT SUM(total) AS total_por_cliente
        FROM  pedidos
        GROUP BY cliente_id
    ) sub
);
Ejemplo 9.2 — Subconsulta en FROM (tabla derivada)SUBQUERY
-- Ranking de categorías por volumen de ventas
SELECT
    resumen.categoria_id,
    resumen.total_vendido,
    resumen.unidades
FROM (
    SELECT
        pr.categoria_id,
        SUM(dp.cantidad * dp.precio_unitario)  AS total_vendido,
        SUM(dp.cantidad)                          AS unidades
    FROM        detalle_pedidos dp
    INNER JOIN  productos        pr ON dp.producto_id = pr.producto_id
    GROUP BY    pr.categoria_id
) resumen
ORDER BY resumen.total_vendido DESC;

10CTEs — WITH (Common Table Expressions)

Las CTEs definen una "consulta nombrada" que puedes referenciar dentro de la consulta principal. Son más legibles que las subconsultas anidadas.

Ejemplo 10.1 — CTE simpleCTE
WITH ventas_por_cliente AS (
    SELECT
        cliente_id,
        COUNT(*)    AS num_pedidos,
        SUM(total) AS total_gastado
    FROM pedidos
    WHERE estado <> 'cancelado'
    GROUP BY cliente_id
)
SELECT
    cl.nombre || ' ' || cl.apellido  AS cliente,
    cl.ciudad,
    v.num_pedidos,
    v.total_gastado
FROM       ventas_por_cliente  v
INNER JOIN clientes            cl  ON v.cliente_id = cl.cliente_id
WHERE      v.num_pedidos >= 5
ORDER BY   v.total_gastado DESC
LIMIT      20;
Ejemplo 10.2 — CTEs múltiples encadenadasCTE
WITH
-- Paso 1: ventas brutas por producto
ventas_producto AS (
    SELECT
        dp.producto_id,
        SUM(dp.cantidad)                         AS unidades,
        SUM(dp.cantidad * dp.precio_unitario)  AS ingresos
    FROM detalle_pedidos dp
    GROUP BY dp.producto_id
),
-- Paso 2: enriquecer con categoría
ventas_enriquecidas AS (
    SELECT
        vp.*,
        pr.nombre         AS producto,
        cat.nombre       AS categoria,
        pr.precio_venta  AS precio
    FROM        ventas_producto vp
    INNER JOIN  productos        pr  ON vp.producto_id  = pr.producto_id
    INNER JOIN  categorias       cat ON pr.categoria_id = cat.categoria_id
)
SELECT categoria, producto, unidades, ingresos
FROM   ventas_enriquecidas
ORDER BY ingresos DESC
LIMIT  15;

11Funciones de Ventana

Las funciones de ventana calculan valores sobre un "grupo" de filas relacionadas sin colapsar las filas en una sola. Usan la cláusula OVER().

Sintaxis generalWINDOW
FUNCION() OVER (
    [PARTITION BY columna]   -- opcional: dividir en grupos
    [ORDER BY     columna]   -- opcional: ordenar dentro del grupo
    [ROWS BETWEEN ...]        -- opcional: ventana deslizante
)
Ejemplo 11.1 — Ranking con ROW_NUMBER y RANKWINDOW
SELECT
    nombre,
    apellido,
    departamento_id,
    salario,
    ROW_NUMBER() OVER (PARTITION BY departamento_id ORDER BY salario DESC) AS posicion,
    RANK()       OVER (PARTITION BY departamento_id ORDER BY salario DESC) AS rank_salario,
    DENSE_RANK() OVER (PARTITION BY departamento_id ORDER BY salario DESC) AS dense_rank
FROM  empleados
ORDER BY departamento_id, posicion;
Ejemplo 11.2 — TOP 3 por departamentoWINDOW
WITH ranking AS (
    SELECT
        nombre, apellido, departamento_id, salario,
        ROW_NUMBER() OVER (PARTITION BY departamento_id ORDER BY salario DESC) AS rn
    FROM empleados
)
SELECT departamento_id, nombre, apellido, salario
FROM  ranking
WHERE rn <= 3
ORDER BY departamento_id, salario DESC;
Ejemplo 11.3 — Acumulados y promedios móvilesWINDOW
WITH ventas_diarias AS (
    SELECT
        fecha_pedido,
        SUM(total) AS venta_dia
    FROM pedidos
    WHERE estado <> 'cancelado'
    GROUP BY fecha_pedido
)
SELECT
    fecha_pedido,
    venta_dia,
    SUM(venta_dia)  OVER (ORDER BY fecha_pedido)  AS acumulado,
    AVG(venta_dia)  OVER (
        ORDER BY fecha_pedido
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    )                                               AS media_movil_7d
FROM  ventas_diarias
ORDER BY fecha_pedido;
Ejemplo 11.4 — LAG y LEAD (comparar con fila anterior/siguiente)WINDOW
WITH ventas_mes AS (
    SELECT
        strftime('%Y-%m', fecha_pedido) AS mes,
        SUM(total) AS venta
    FROM pedidos
    WHERE estado <> 'cancelado'
    GROUP BY 1
)
SELECT
    mes,
    venta,
    LAG(venta)  OVER (ORDER BY mes)  AS mes_anterior,
    ROUND((venta - LAG(venta) OVER (ORDER BY mes))
         / LAG(venta) OVER (ORDER BY mes) * 100, 2) AS cambio_pct
FROM ventas_mes
ORDER BY mes;

12CASE — Lógica condicional

CASE es el IF/ELSE de SQL. Permite calcular valores condicionales dentro de una consulta.

Ejemplo 12.1 — Categorizar datosCASE
SELECT
    nombre,
    precio_venta,
    CASE
        WHEN precio_venta <  500   THEN 'Económico'
        WHEN precio_venta <  3000  THEN 'Gama Media'
        WHEN precio_venta <  10000 THEN 'Gama Alta'
        ELSE                              'Premium'
    END AS segmento,
    stock,
    CASE
        WHEN stock = 0             THEN 'Sin stock'
        WHEN stock < stock_minimo  THEN 'Stock bajo'
        ELSE                              'Disponible'
    END AS estado_stock
FROM  productos
ORDER BY precio_venta;
Ejemplo 12.2 — CASE en GROUP BY (pivot)CASE
-- Contar pedidos por estado usando columnas separadas
SELECT
    COUNT(CASE WHEN estado = 'entregado'   THEN 1 END) AS entregados,
    COUNT(CASE WHEN estado = 'cancelado'   THEN 1 END) AS cancelados,
    COUNT(CASE WHEN estado = 'procesando'  THEN 1 END) AS procesando,
    COUNT(CASE WHEN estado = 'pendiente'   THEN 1 END) AS pendientes,
    SUM(CASE WHEN metodo_pago = 'tarjeta_credito' THEN total ELSE 0 END) AS venta_credito
FROM  pedidos;

13Funciones de Cadena de texto

Ejemplo 13.1 — Manipulación de textoSTRING
SELECT
    nombre,
    apellido,
    UPPER(nombre)                                    AS nombre_upper,

14Funciones de Fecha

Ejemplo 14.1 — Cálculos con fechas (SQLite)DATE
SELECT
    pedido_id,
    fecha_pedido,
    fecha_entrega,
    julianday(fecha_entrega) - julianday(fecha_pedido)   AS dias_entrega,
    strftime('%Y', fecha_pedido)                        AS anio,
    strftime('%m', fecha_pedido)                        AS mes,
    strftime('%w', fecha_pedido)                        AS dia_semana
FROM  pedidos
WHERE estado = 'entregado'
  AND julianday(fecha_entrega) - julianday(fecha_pedido) > 7;

-- PostgreSQL equivalente:
-- (fecha_entrega - fecha_pedido) AS dias_entrega
-- EXTRACT(YEAR FROM fecha_pedido) AS anio
Ejemplo 14.2 — Antigüedad de clientes y empleadosDATE
-- Empleados contratados hace más de 2 años
SELECT
    nombre, apellido, puesto, fecha_contrato,
    ROUND((julianday('now') - julianday(fecha_contrato)) / 365.25, 1) AS antiguedad_anios
FROM  empleados
WHERE julianday('now') - julianday(fecha_contrato) > 730
ORDER BY antiguedad_anios DESC;

Nivel 2 — Intermedio

  1. Muestra el total de ventas (sum) y el número de pedidos por método de pago, solo para pedidos entregados.
  2. Lista los productos que tienen stock por debajo de su stock_mínimo. Incluye nombre, marca, stock actual y stock_mínimo.
  3. ¿Cuál es el ticket promedio por tipo de cliente? Excluye cancelados.
  4. Encuentra los 5 empleados con mayor salario de cada departamento.
  5. Lista los clientes que compraron más de 3 veces en un solo mes (cualquier mes).

Nivel 3 — Avanzado

  1. Calcula el margen de ganancia real por categoría: (precio_venta - precio_compra) / precio_compra * 100 promedio, ponderado por unidades vendidas.
  2. Identifica los clientes que compraron en 2023 pero NO compraron en 2024. Usa subconsultas o NOT EXISTS.
  3. Genera un reporte de crecimiento mensual de ventas: muestra el mes, las ventas del mes, las ventas del mes anterior y el porcentaje de cambio. Usa funciones de ventana LAG.
  4. Encuentra los "mejores vendedores" por región: el empleado con mayor suma de ventas en cada region_id. Usa CTE y ROW_NUMBER.
  5. Crea un análisis RFM básico (Recency, Frequency, Monetary) para cada cliente: días desde la última compra, número total de pedidos y monto total gastado.
